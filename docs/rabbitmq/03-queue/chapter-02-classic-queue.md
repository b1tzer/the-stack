# Classic Queue

> Classic Queue 是 RabbitMQ 最早的队列类型。理解它是理解 Quorum Queue 的基础。

## 1. Classic Queue 的存储结构

```txt
┌──────────────────────────────────────────┐
│            Classic Queue                 │
│                                          │
│  ┌─────────────────────────────────────┐ │
│  │  Q1 (内存，未确认)                   │ │
│  │  [msg1][msg2][msg3]                 │ │
│  └─────────────────────────────────────┘ │
│  ┌─────────────────────────────────────┐ │
│  │  Q2 (内存引用，指向磁盘)             │ │
│  │  [ref1][ref2][ref3]                 │ │
│  └─────────────────────────────────────┘ │
│  ┌─────────────────────────────────────┐ │
│  │  Delta (磁盘，未读)                  │ │
│  │  [msg4][msg5][msg6]...              │ │
│  └─────────────────────────────────────┘ │
│  ┌─────────────────────────────────────┐ │
│  │  Q3 (磁盘索引)                       │ │
│  └─────────────────────────────────────┘ │
└──────────────────────────────────────────┘
```

Classic Queue 使用一种混合存储：热数据在内存（Q1），冷数据在磁盘（Delta），中间有索引（Q2/Q3）。

## 2. 消息流转

```txt
消息进入 → Q1（内存）
  │
  ├─ 内存够 → 一直在 Q1，直接消费
  └─ 内存不够 → 换页到磁盘（Delta），Q2 存引用
  
消费时：
  Q1 有消息 → 直接从 Q1 取
  Q1 空了 → 从 Delta 读磁盘 → 加载到 Q1
```

## 3. Classic Queue 的局限

| 问题 | 说明 |
| :-- | :-- |
| 镜像队列已废弃 | 3.x 版本中，Mirrored Queue 被 Quorum Queue 取代 |
| 内存瓶颈 | 消息堆积时换页到磁盘，消费性能下降 |
| 不支持流控回压 | 生产速度远大于消费速度时，可能撑爆内存 |
| 故障恢复慢 | Broker 崩溃后需要从磁盘重建索引 |

## 4. Classic Queue 参数

| 参数 | 默认值 | 说明 |
| :-- | :-- | :-- |
| x-max-length | 不限 | Queue 最大消息数 |
| x-max-length-bytes | 不限 | Queue 最大字节数 |
| x-overflow | drop-head | 超限时行为：drop-head（丢最老）/ reject-publish |
| x-message-ttl | 不限 | 消息 TTL（毫秒） |
| x-expires | 不限 | Queue 空闲超时自动删除 |
| x-max-priority | 0 | 最大优先级（0=不启用） |
| x-dead-letter-exchange | 无 | 死信 Exchange |
| x-dead-letter-routing-key | 原 key | 死信 routing key |

## 5. 什么时候还用 Classic Queue

- 已有系统在用 Classic Queue，且运行稳定
- 不需要高可用（单节点场景）
- 临时队列（排他、自动删除）
- 需要优先级队列（Classic Queue 原生支持 x-max-priority）

**新项目建议直接用 Quorum Queue。**

## 6. Classic Queue vs Quorum Queue

| 维度 | Classic Queue | Quorum Queue |
| :-- | :-- | :-- |
| 高可用 | 镜像队列（已废弃） | Raft 协议（内置） |
| 持久性 | 可选 | 强持久 |
| 性能 | 更高（无共识开销） | 稍低（Raft 共识） |
| 消息丢失风险 | 有（镜像异步复制） | 极低（多数确认） |
| 适用场景 | 临时队列、低可靠需求 | 生产环境、高可靠需求 |
