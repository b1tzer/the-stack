# 网络通信与协议分析

很多程序要联网——下载更新、上报数据、调用服务。分析这类程序，目标往往是**还原它的网络协议**：它发了什么、收什么、数据怎么编码。这一章讲协议分析的思路和方法。

## 1. 网络逆向的切入点

分析程序网络行为的入口，是网络相关的 API。程序要联网，一定会调用这些函数：

- **Winsock**：`socket`、`connect`、`send`、`recv`（`ws2_32.dll`）。
- **HTTP**：`WinHTTP`、`WinINet`（`winhttp.dll`、`wininet.dll`），或封装好的 HTTP 库。
- **加密**：`CryptEncrypt`、`EncryptMessage`，或 TLS 库（如 OpenSSL、SChannel）。

反汇编里定位到这些调用，就找到了「网络行为发生的地方」。从 `connect` 能看出连到哪个地址（参数里的 IP/端口），从 `send`/`recv` 能看出收发了什么数据。

## 2. 抓包 + 反汇编对照

协议分析的标准方法，是**抓包和反汇编对照**：

1. **抓包**：用 Wireshark、Fiddler 等工具，抓到程序实际收发的网络流量。
2. **反汇编**：找到程序里 `send`/`recv` 的调用点，看它收发数据前后的处理逻辑。
3. **对照**：把抓到的数据（协议字节）和反汇编（数据的生成/解析逻辑）对应起来。

抓包告诉你「线上跑了什么」，反汇编告诉你「程序为什么这么编码」。两者对照，才能还原协议的完整含义。

## 3. 从反汇编还原协议格式

协议的核心是「数据怎么编码」。常见编码在反汇编里有对应特征：

- **长度前缀**：先写一个长度，再写数据。反汇编里是「先写入一个数，再 memcpy 数据」。
- **固定字段**：按固定偏移读写各字段。反汇编里是「基址 + 偏移」的访问。
- **序列化**：用结构体或流式序列化（类似上一章的 `QDataStream`）。
- **校验和/哈希**：数据末尾跟一段校验值。反汇编里是「对数据做循环运算，结果附在末尾」。

还原协议的方法：在 `send` 调用前下断点，看内存里「即将发送的缓冲区」是什么结构；在 `recv` 后下断点，看「收到的数据」如何被解析。

## 4. 加密通信的识别与应对

很多程序的通信是加密的（TLS 或自定义加密）。识别信号：

- 抓包里看到的是密文（乱码），不是明文协议。
- 反汇编里看到 `EncryptMessage`、OpenSSL 的 `SSL_write` 等加密调用。
- 数据收发前后有「明显的变换循环」（自定义加密）。

应对策略：

- **TLS 加密**：如果是标准 TLS，抓包工具配合证书/密钥可以解密；或用调试器在「加密前/解密后」的关键点（`SSL_write` 前后）看明文。
- **自定义加密**：在加密函数前后下断点，看「加密前的明文」和「解密后的明文」，还原加密算法。

关键思路：**在数据被加密前、解密后，数据是明文**。调试器的作用就是停在「加密前后」这两个关键时刻，看到明文。

## 5. 协议分析的产物

协议分析的目标，通常是产出：

- **协议格式文档**：每个字段的含义、长度、编码方式。
- **可能的自动化脚本**：能解析或生成该协议的工具。
- **对程序行为的理解**：它上报了什么、接收了什么指令。

这些产物用于安全研究、互操作性分析（在合法授权范围内）、或恶意软件分析（理解 C2 通信）。

## 6. 一个典型流程

以分析一个「向服务器上报数据」的程序为例：

1. 抓包，看到程序周期性向某个 IP 发数据。
2. 反汇编，定位 `connect`，确认目标 IP/端口。
3. 定位 `send`，在它前面下断点，看「即将发送的缓冲区」。
4. 分析缓冲区的生成逻辑（反汇编里往上追），还原数据格式。
5. 在 `recv` 后下断点，看「收到的响应」如何被解析。

这一套流程走下来，就能还原出「程序上报什么、服务器回什么、数据怎么编码」。

## 7. 完整实例：还原一个上报协议

用一个「周期上报温度」的小程序，走一遍协议还原。

```c
void report_temperature(int sock, int temp) {
    char buf[64];
    int len = sprintf(buf, "TEMP:%d\r\n", temp);
    send(sock, buf, len, 0);
}
```

**第一步：字符串直接暴露协议格式。** 这个程序很典型——协议格式串 `"TEMP:%d\r\n"` 是明文常量。用字符串搜索（`strings` 或反汇编器的字符串视图）直接就能看到它，立刻得知协议是「`TEMP:` 前缀 + 十进制温度值 + CRLF 结尾」。

**第二步：反汇编对照，确认字段语义。** 在反汇编里追这个格式串的引用，看到它被传给 `sprintf`：

```asm
lea  rcx, [rip + "TEMP:%d\r\n"]  ; 格式串
mov  edx, [temp]                  ; 温度值
call sprintf                       ; 拼成 "TEMP:23\r\n"
lea  rdx, [buf]
mov  ecx, [sock]
call send                          ; 发送
```

这样，协议的三个字段就还原出来了：字段名 `TEMP`、字段值（十进制整数）、分隔符 `\r\n`。

**第三步：抓包验证。** 用 Wireshark 抓包，会看到程序实际发出 `TEMP:23\r\n`，和反汇编推导完全吻合。

这个例子简单，但揭示了协议还原的核心规律：**协议格式串在反汇编里是明文，找到它就能还原格式；找不到（格式串被加密）才需要动态调试在 `send` 前看缓冲区。** 真实程序的协议可能更复杂（二进制、带校验、加密），但方法不变——静态找格式串，动态看 `send` 前的缓冲区，两者互相印证。
