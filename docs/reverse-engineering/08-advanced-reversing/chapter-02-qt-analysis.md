# Qt 程序分析：信号槽与序列化

Qt 是 Windows 上广泛使用的 C++ 框架，很多桌面软件（尤其是带界面的工具）用 Qt 编写。Qt 有一套独特的机制——信号槽、元对象系统、序列化——理解这些，才能看懂 Qt 程序的反汇编。

## 1. 如何识别 Qt 程序

分析前先判断「这是不是 Qt 程序」，几个信号：

- 字符串里出现 `Qt5`、`Qt6`、`QObject`、`QWidget` 等字样。
- 导入 `Qt5Core.dll`、`Qt5Gui.dll`、`Qt5Widgets.dll` 等 DLL。
- 反汇编里出现大量以 `Q` 开头的类名（有符号时）。

确认是 Qt 后，就能用 Qt 的知识框架去理解它。

## 2. 信号槽机制

信号槽（signal/slot）是 Qt 的核心通信机制。它的实现依赖 **moc（Meta-Object Compiler）**：编译前，moc 从带 `Q_OBJECT` 宏的类生成额外的元数据代码。

信号槽对逆向的影响：

- 信号和槽不是普通函数调用，而是通过**元对象系统**间接连接和分派的。
- 一个 `connect(sender, SIGNAL(...), receiver, SLOT(...))`，运行时会建立信号到槽的映射。
- 反汇编里，信号槽的分派表现为「查元数据表 → 间接调用槽函数」。

识别要点：反汇编里看到 `QMetaObject`、`qt_metacall`、`qt_static_metacall` 这些符号（有符号时），就进入了 Qt 的信号槽体系。无符号时，通过「查表间接调用」的模式识别。

## 3. 元对象系统

每个 `QObject` 派生类，都有一个 `QMetaObject` 描述它：类名、信号列表、槽列表、属性列表。这些元数据以字符串和表的形式存在二进制里。

对逆向的价值：**元数据里存了类名、信号名、槽名**。即使程序无符号，反汇编器或手动分析也能从元数据里恢复出这些名字，快速理解「这个类有哪些信号和槽」。

这也是 Qt 程序相对好逆向的原因之一：框架的元数据泄露了类结构信息。

## 4. 序列化：QDataStream

Qt 的序列化用 `QDataStream`，它把数据按固定格式写入二进制流。逆向 Qt 程序时，经常要理解「某个二进制文件/数据块是怎么序列化的」。

`QDataStream` 的格式特征：

- 数据按「类型 + 值」编码，类型信息可能带版本号。
- 字符串前有长度前缀。
- 序列化的格式与 Qt 版本相关。

逆向思路：如果程序读写某个配置文件或数据文件，先定位 `QDataStream` 的读写调用，再对照文件的实际字节，还原出序列化格式。这通常需要「静态分析（看代码）+ 动态调试（看真实数据）」结合。

## 5. 配置文件：QSettings

Qt 程序常用 `QSettings` 读写配置，底层是 INI 文件或注册表。

逆向时，看到程序读写配置文件，先确认它用 `QSettings` 还是自定义格式：

- `QSettings`：格式标准（INI/注册表），直接看配置文件即可理解键值含义。
- 自定义格式：需要按上一节的方法，还原序列化/解析逻辑。

很多 Qt 程序把「关键配置」（如授权信息、功能开关）放在配置文件里，理解配置文件格式，往往直接关系到理解程序的核心逻辑。

## 6. 分析策略

分析 Qt 程序，建议的顺序：

1. 确认是 Qt，确定版本（影响序列化格式）。
2. 从元对象系统恢复类名、信号、槽名。
3. 从信号槽的连接关系，理解「用户操作 → 程序响应」的流程。
4. 分析关键槽函数的逻辑（这就是业务逻辑所在）。
5. 如涉及文件/配置，还原序列化格式。

Qt 程序因为元数据丰富、结构规整，相比手写的裸 C++ 程序往往更好分析。

## 7. 完整实例：识别一个信号发射点

用一个最小 Qt 类，看「发射信号」在反汇编里长什么样。

```cpp
class Worker : public QObject {
    Q_OBJECT
public slots:
    void doWork();
signals:
    void finished();
};

void Worker::doWork() {
    emit finished();
}
```

分析这个程序时，两个指纹能帮你定位信号槽体系：

**指纹一：`QMetaObject::activate`。** `emit finished()` 编译后不是直接调用某个函数，而是调用 Qt 运行时的 `QMetaObject::activate`，由它查元数据、找到所有连接的槽并逐个调用：

```asm
lea  rdx, [rip + finished_signal_index]  ; 信号的索引
mov  rcx, [this]                          ; this（QObject*）
call QMetaObject::activate                ; 激活信号
```

看到 `QMetaObject::activate`，就找到了「信号发射点」；`finished_signal_index` 对应的元数据条目里，存着信号的字符串名 `"finished"`。

**指纹二：moc 生成的元数据字符串。** 因为 `SIGNAL(finished())` 和 `SLOT(doWork())` 宏会把名字编译成字符串常量，反汇编/字符串视图里能直接搜到：

```text
"2finished()"   ; 2 = 信号
"1doWork()"     ; 1 = 槽
```

这两个字符串是 Qt 信号槽最直接的暴露。顺着它们的交叉引用，能追到 `connect` 调用，进而还原「谁发信号、谁接槽」的完整连接关系。

**识别流程总结**：搜 `QMetaObject::activate` 定位发射点 → 从信号索引的元数据拿到信号名 → 从 `"1槽名"` 字符串追到槽实现 → 分析槽函数里的业务逻辑。
