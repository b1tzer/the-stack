# 手动脱壳：找 OEP、Dump 与修 IAT

当没有现成脱壳工具时，需要手动脱壳。完整流程分三步，无论什么壳都逃不出这个框架：**找 OEP → dump 内存 → 修 IAT**。这一章逐步拆解。

## 1. 第一步：找 OEP

让程序运行到「壳已还原、即将跳原始入口」的那一瞬间，就是 OEP。常用三种方法：

**ESP 定律**（最常用）。壳的 stub 开头常有 `pushad`/`pushfd`（保存所有寄存器），此时对栈顶 `ESP` 下**硬件断点**（访问），然后 `F9` 运行。壳还原完成后会 `popad` 恢复寄存器并访问栈，命中硬件断点停下，附近往往就是跳向 OEP 的 `jmp`。

**单步跟踪**。从壳入口一路单步，直到出现一次**大范围跳转**（跨节区的 `jmp`），那个目标常是 OEP。这个方法慢，但能看清壳的还原过程。

**内存断点法**。对 `UPX0` 这类「运行时才填充」的节下内存访问断点，命中时壳已解压完成。

三种方法的共同思路是：**抓住「壳还原完成」这个信号**——无论是寄存器被恢复、还是代码段被填充、还是发生跨节区跳转。

## 2. 第二步：dump 内存

停在 OEP 后，此刻内存里已经是完整的、还原后的程序。用调试器的 dump 功能（x64dbg 的 Scylla 插件，或 OllyDbg 时代的 OllyDump）把当前进程镜像 dump 出来，存成新的文件。

关键点：**必须在 OEP 处 dump**，因为只有此刻，内存里的代码和数据才是「已还原」的完整状态。dump 早了，代码还没解压完；dump 晚了，程序可能已经进入运行状态、内存被改动。

## 3. 第三步：修复导入表

dump 出来的文件有个问题：它的导入表（IAT）里的函数地址是「当前运行时的真实地址」，脱离这个进程环境就失效了（因为 ASLR，下次运行的基址不同，这些地址不再有效）。

需要用 **Scylla（或 ImportREC）** 分析 dump 文件、重建导入表：

1. 让 Scylla 定位 dump 文件里的 IAT。
2. Scylla 扫描 IAT 里的函数地址，反查它们属于哪个 DLL 的哪个函数。
3. 重建导入表，把「运行时地址」换回「函数名/序号」，恢复成正常的 PE 结构。

三步做完，你就得到一个「脱壳后的程序」，可以用 [IDA Pro](../05-static-analysis/chapter-04-ida-pro.md) 或 [Ghidra](../05-static-analysis/chapter-05-ghidra.md) 正常分析了。

## 4. 练习建议

手动脱壳是逆向的中级技能，第一次做几乎必然在「找 OEP」或「修 IAT」卡住。建议按这个顺序练习：

1. 先用 UPX 加壳一个自己写的程序。
2. 用 `upx -d` 脱一次，确认「脱壳后的正确结果」长什么样。
3. 再手动脱一次（ESP 定律找 OEP → dump → Scylla 修 IAT），对照自动脱壳的结果。

体会每一步在做什么，再挑战更复杂的壳。
