# 常见编译器代码模式

掌握了寄存器、指令、调用约定后，读汇编的下一步是**识别模式**：一段高级语言结构（`if`、循环、`switch`、结构体访问）编译后会变成什么样子。认出了模式，就能快速把一大段汇编「翻译」回高级语言。

## 1. 条件判断：cmp + jcc

几乎所有的 `if`，编译后都是「比较 + 条件跳转」：

```c
if (x == 0) {
    do_a();
} else {
    do_b();
}
```

编译后形如：

```asm
cmp  eax, 0
jne  else_label     ; 不等于 0 就跳到 else
call do_a
jmp  end_label
else_label:
call do_b
end_label:
```

识别要点：**`cmp`/`test` 紧跟 `jcc`，就是一次条件判断**。跳转方向反着读——`je`（等于则跳）对应 `!=` 的条件，`jne`（不等则跳）对应 `==` 的条件。

## 2. 逻辑与或：短路求值

`&&` 和 `||` 有短路语义，编译后是「串联的条件跳转」：

```c
if (a && b) { ... }
```

编译后形如：

```asm
test eax, eax        ; 检查 a
je   skip            ; a 为假，直接跳过（短路）
test ebx, ebx        ; 检查 b
je   skip            ; b 为假，跳过
...                  ; a 和 b 都为真，执行这里
skip:
```

识别要点：**连续多个 `test` + `je`（或 `jne`）跳到同一个目标，是 `&&`（全真才进）或 `||`（一真就进）的短路**。

## 3. switch：跳转表

`switch` 有两种编译方式：

- **分支少**：退化成 `if-else` 链。
- **分支多且连续**：用**跳转表（jump table）**——把每个 case 的地址放进一张表，用索引直接跳转。

跳转表的特征反汇编里很显眼：

```asm
movsxd rax, dword ptr [rdx+rax*4]   ; 用 case 值做索引查表
add    rax, rdx
jmp    rax                           ; 跳转到查表结果
```

看到「用变量做索引查一张表，然后间接跳转」，基本就是 `switch` 的跳转表实现。

## 4. 循环：for / while

循环的典型形态是「初始化 + 条件判断 + 循环体 + 回跳」：

```asm
mov  ecx, 0          ; i = 0
loop_start:
cmp  ecx, 10         ; i < 10 ?
jge  loop_end        ; 不满足就退出
...                  ; 循环体
inc  ecx             ; i++
jmp  loop_start      ; 回跳
loop_end:
```

识别要点：**一个向上的跳转（跳回前面）通常就是循环**。判断循环变量、循环条件，就能还原出 `for (i=0; i<10; i++)` 这种结构。

## 5. 结构体与数组访问

结构体成员和数组元素，编译后都是「基址 + 偏移」的寻址：

```c
struct Point { int x; int y; };
p->y = 10;
```

编译后形如：

```asm
mov  eax, 10
mov  [rcx+4], eax    ; y 在偏移 4 处（x 占 0-3）
```

数组访问则是「基址 + 索引 × 元素大小」：

```asm
mov  eax, [rdx+rax*4]   ; arr[i]，元素 4 字节
```

识别要点：**`[寄存器 + 常数]` 通常是结构体成员，`[基址 + 索引×缩放]` 通常是数组**。这也是恢复结构体和数组的线索。

## 6. 除以常数：魔法数

除以一个**编译期常数**，编译器会做优化：不直接 `div`（除法指令很慢），而是乘一个「魔法数」再移位。

所以反汇编里看到「乘以一个奇怪的常数 + 右移」，别以为是算法，很可能就是一个普通的除法：

```asm
mov  eax, ecx
imul eax, eax, 0x55555556   ; 魔法数
...                          ; 再右移、调整
```

看到 `imul` 一个奇怪的常数，先怀疑是「除以某个常数」的优化，而不是复杂的算术。

## 7. MSVC 与 GCC 的差异

不同编译器生成的代码风格不同，识别出来能帮你判断程序的构建环境：

| 特征 | MSVC | GCC/MinGW |
| :-- | :-- | :-- |
| 函数名修饰 | `?func@@YA...`（C++） | `_Z4func...`（Itanium） |
| 栈帧 | 常用 `rbp` 帧指针 | 优化后常用 `rsp` |
| 字符串 | `lea rcx, "..."` | 类似，但细节不同 |
| 内联汇编 | `__asm` 语法 | AT&T 或 Intel 语法 |

判断编译器对逆向有帮助：知道是 MSVC 还是 GCC，就能预期代码风格、函数名修饰方式，从而更快地识别函数和结构。
