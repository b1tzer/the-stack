# x86 汇编基础

本专题主线是 x64，但很多老程序、老壳、老工具仍是 32 位 x86。理解 x86 与 x64 的差异，才能在遇到 32 位目标时从容切换。这一章讲 x86 的核心：寄存器、寻址、调用约定，重点放在它与 x64 的不同。

## 1. 寄存器：32 位，更少

x86 有 8 个通用寄存器，每个 32 位：

```text
EAX  EBX  ECX  EDX  ESI  EDI  EBP  ESP
```

和 x64 的关系：x64 的这些寄存器是 64 位扩展版（`RAX` 是 `EAX` 的 64 位版）。x86 只有 8 个寄存器，比 x64 的 16 个少，因此编译器更依赖栈来存临时值。

特殊寄存器：

- **EIP**：指令指针（x64 的 RIP 的 32 位版）。
- **EFLAGS**：标志寄存器。
- **ESP**：栈指针（几乎只用于栈顶）。

## 2. 调用约定：栈传参 vs 寄存器传参

x86 和 x64 最大的区别在**调用约定**。x86 有多个约定，但都靠**栈**传参；x64 统一用寄存器传前几个参数。

**cdecl**（C 默认约定）：

- 参数从右到左压栈。
- 调用者负责清理栈（`add esp, N`）。
- 支持变参（如 `printf`）。

**stdcall**（Win32 API 约定）：

- 参数从右到左压栈。
- 被调函数负责清理栈（`ret N`）。
- Win32 API（`kernel32` 等 32 位版）都用这个。

**fastcall**：

- 前两个参数用 `ECX`、`EDX`，其余压栈。

对比记忆：**x86 参数在栈上，x64 参数在寄存器里。** 这是两代架构最影响读反汇编的差异。

看一个 cdecl 调用的例子，调用 `add(3, 5)`：

```asm
push 5          ; 参数从右到左，先压 5
push 3          ; 再压 3
call add        ; 调用
add  esp, 8     ; 调用者清理 8 字节栈（两个 int）
```

而同样的调用在 x64 下是 `mov ecx, 3; mov edx, 5; call add`，参数直接进寄存器。

## 3. 栈帧：push ebp 的经典模式

x86 的栈帧建立非常典型，几乎每个函数开头都是：

```asm
push ebp        ; 保存旧帧指针
mov  ebp, esp   ; 建立新帧指针
sub  esp, 40h   ; 为局部变量留空间
```

结尾对应：

```asm
mov  esp, ebp   ; 恢复栈顶
pop  ebp        ; 恢复旧帧指针
ret
```

`EBP` 作为帧指针，`[ebp - 偏移]` 访问局部变量，`[ebp + 偏移]` 访问参数。这个「push ebp / mov ebp, esp」的模式，是识别 x86 函数边界的标志。

而在 x64 下，编译器常常**省略帧指针**，直接用 `RSP` 计算偏移，所以看不到这个模式。这是识别「这是 32 位还是 64 位代码」的一个线索。

## 4. 数据宽度与指令

x86 操作 32 位数据，常用宽度后缀是 `byte`、`word`、`dword`。指令集和 x64 大部分重合，但 x64 扩展了 64 位操作（`rax`、`qword`）。

一个常见现象：x86 反汇编里 `mov eax, [esp+4]` 这种「用 ESP 直接访问参数」的写法很常见（因为没有多余寄存器），x64 里则更多用 `rsp` 或帧指针。

## 5. 什么时候会遇到 x86

虽然本专题主线是 x64，但你会在这几种场景遇到 x86：

- 分析老的 32 位程序、老壳、老插件。
- 32 位 DLL 被 64 位程序通过 WoW64 兼容层加载。
- 一些 shellcode 仍是 32 位（体积更小）。

遇到 x86 目标时，用 x32dbg（而不是 x64dbg）调试，用 32 位视角读反汇编，注意参数在栈上、寄存器更少这两个核心差异。
