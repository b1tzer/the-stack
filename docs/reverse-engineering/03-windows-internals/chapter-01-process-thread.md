# 进程与线程

逆向分析的对象，是运行中的进程。这一章讲 Windows 里最基础的两个概念——进程和线程，它们是理解「程序如何运行、调试器在调试什么」的前提。

## 1. 进程：资源的容器

进程（process）是操作系统资源分配的基本单位。一个进程拥有：

- 一个独立的虚拟地址空间（上一章讲过）。
- 已加载的模块（`.exe` 和依赖的 `.dll`）。
- 堆、栈、句柄表等资源。
- 至少一个线程。

进程之间相互隔离：一个进程不能直接读写另一个进程的内存。调试器之所以能「看」目标进程的内存，是因为它通过操作系统的调试接口获得了特殊权限，而不是突破了隔离。

## 2. 线程：执行的单位

线程（thread）是 CPU 调度的基本单位，是真正「执行代码」的东西。一个进程可以有多个线程，它们共享进程的地址空间和资源，但各自有独立的：

- 栈（每个线程一个栈）。
- 寄存器上下文（一组寄存器值）。
- 异常处理链。

CPU 在多个线程之间切换执行，每次切换都要保存/恢复寄存器上下文。这个「切换」就是上下文切换（context switch）。

## 3. 逆向中如何看进程和线程

调试器里，这些概念有直接的对应：

| 概念 | 调试器里的对应 |
| :-- | :-- |
| 进程 | 你正在调试的整个目标 |
| 线程 | 调试器里可以切换的各个线程 |
| 寄存器上下文 | 切换线程后看到的寄存器面板 |
| 每个线程的栈 | 栈面板显示当前线程的栈 |

理解这些对应关系，能解释几个常见现象：

- **断点是进程级的还是线程级的**：软件断点（`INT 3`）命中时，哪个线程执行到那里，哪个线程停下；其他线程可能还在跑。
- **调用栈属于线程**：栈面板显示的调用链，是「当前线程」的调用链，不是整个进程的。
- **多线程程序的断点命中顺序不确定**：哪个线程先执行到断点，取决于调度，所以多线程程序的调试现象可能每次不同。

## 4. 线程上下文：调试器「暂停」的本质

调试器让程序「停在某一行」，本质是：

1. 通过调试事件让目标进程的某个线程停下。
2. 读取该线程的上下文（`GetThreadContext`），得到它此刻的寄存器值、指令指针（RIP）。
3. 调试器把 RIP 指向的地址显示成「当前停在的位置」。

所以你在调试器里看到的「程序状态」，本质是「某个线程在某个瞬间的寄存器快照」。理解了这一点，就理解了动态调试的核心——它观察的是线程的执行快照。
