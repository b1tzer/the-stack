# 虚拟内存与内存保护

PE 格式讲的是「文件」，这一章讲「运行」：程序被加载进内存后，内存如何布局、如何保护。理解这些，才能看懂调试器里的内存地址，解释为什么同一个程序每次运行的地址不一样。

## 1. 虚拟内存：每个进程都有一套假地址

每个 Windows 进程看到的内存，都是**虚拟内存**——一套属于它自己的、独立的地址空间。进程 A 和进程 B 可能都认为自己访问 `0x140000000`，但它们映射到的物理内存完全不同。

虚拟内存按**页**（page）管理，一页通常是 4 KB。进程不是一启动就占满整个地址空间，而是按需映射：只有真正用到的页才会对应到物理内存，其余地址要么未分配，要么保留但未提交。访问一个未映射的地址，会触发**访问违例（access violation）**——你在调试器里看到的崩溃，很多就源于此。

对逆向的意义：**内存地址是「虚拟」的，你在调试器里看到的地址要放在「这个进程的地址空间」里去理解，不能直接拿去和文件偏移划等号。**

## 2. 用户态与内核态的划分

Windows x64 把 64 位地址空间劈成两半：

| 范围 | 归属 |
| :-- | :-- |
| `0x00000000_00000000` ～ `0x00007FFF_FFFFFFFF` | 用户态，程序代码和数据在这里 |
| `0xFFFF8000_00000000` 及以上 | 内核态，系统内核和驱动在这里 |

用户态程序不能直接访问内核态地址，系统调用（syscall）通过 `ntdll.dll` 转进内核。逆向用户态程序时，你关心的几乎都在用户态范围内；反汇编窗口里地址以 `0x00007FF...` 开头是常态，以 `0xFFFF...` 开头则说明进入了内核态相关代码（普通用户态分析很少遇到）。

## 3. 一个进程的内存大致长什么样

把上面的概念落到一张图。一个典型的用户态进程，其内存（从低地址到高地址）大致是：

```text
低地址
+--------------------------+
|  NULL 区（前 64KB 保留）  |  ← 防止空指针被误用
+--------------------------+
|  主模块 .exe 的映像        |  ← 代码、数据、导入表等按节区映射进来
+--------------------------+
|  各 DLL 的映像             |  ← ntdll.dll、kernel32.dll、user32.dll ...
+--------------------------+
|  堆（heap）               |  ← 动态分配，new/malloc 的内存在这
+--------------------------+
|  栈（stack）              |  ← 函数调用、局部变量，向下生长
+--------------------------+
|  共享内存 / 映射文件 等    |
+--------------------------+
高地址（用户态边界 0x7FFF_FFFFFFFF）
```

几点值得注意：

- **映像区**是 PE 文件「映射」进内存的结果，节区按 `SectionAlignment` 对齐，和文件里的布局不完全一样（对应 PE 加载过程的文件偏移与 RVA 区别）。
- **堆**由堆管理器分配，多个分配之间不连续，地址无规律。
- **栈**是固定上限的一块区域，向下生长；每个线程都有自己的栈。
- 栈和堆的**增长方向相反**，中间的空隙是未映射区。

调试器里看内存地址时，先判断它落在哪个区：`0x1400...` 开头多半是主模块，`0x00007FF...` 开头多半是某个系统 DLL，一个很小的地址可能是空指针或栈上的局部变量。

## 4. 内存保护与安全缓解机制

Windows 给进程内存页施加权限（读 / 写 / 执行），这也是 PE 节区权限在内存里的体现。同时还有几项安全缓解机制，直接影响你的分析体验：

| 机制 | 作用 | 对分析的影响 |
| :-- | :-- | :-- |
| ASLR | 随机化模块、堆、栈的基址 | 绝对地址每次运行都变，必须用「基址 + 偏移」定位 |
| DEP（数据执行保护） | 数据页不可执行，防止栈/堆上执行代码 | 直接往栈上写 shellcode 并跳转会被拦截 |
| CFG（控制流保护） | 限制间接调用的目标 | 部分异常跳转/ROP 手法被阻断 |

这些机制的存在，意味着**现代 Windows 逆向不能套用十几年前的老教程里「栈上执行代码」那套做法**。[反调试与反静态分析](../07-packing/chapter-03-virtualization-anti-debugging.md)讲对抗时会回到这些机制上。
