# 内存模型与函数调用

在进入汇编之前，先用 C 语言的视角理解两件事：程序的内存分几块、函数调用时发生了什么。这两个概念是后面读汇编、看栈帧的共同基础。

## 1. 程序的内存分几块

一个运行中的程序，其内存大致分为几块：

| 区域 | 存什么 | 生命周期 |
| :-- | :-- | :-- |
| 代码段（.text） | 编译后的机器码 | 整个程序运行期间 |
| 数据段（.data / .rdata） | 全局变量、静态变量、常量 | 整个程序运行期间 |
| 堆（heap） | 动态分配的内存（`malloc`/`new`） | 手动分配、手动释放 |
| 栈（stack） | 局部变量、函数调用信息 | 函数调用期间 |

其中**栈**和**堆**是逆向里反复出现的两个概念，必须分清：

- **栈**：由编译器自动管理，函数调用时分配、返回时释放。速度快，但容量有限，只能存局部变量和调用信息。
- **堆**：由程序显式管理，灵活但需要手动释放，分配和释放的时机由程序逻辑决定。

在反汇编里，栈上的变量通过 `[rsp + 偏移]` 访问，堆上的对象通过指针（寄存器里存地址）访问。

## 2. 指针：内存的地址

指针是 C 语言里最核心、也是逆向里最需要理解的概念。一个指针就是一个**内存地址**，它指向内存里某个位置的数据。

```c
int x = 42;      // x 在栈上，值是 42
int* p = &x;     // p 存的是 x 的地址
*p = 10;         // 通过地址改 x 的值
```

在反汇编里，指针表现为「寄存器里存着一个地址，然后 `[寄存器]` 去读那个地址的内容」。看到 `mov rax, [rcx]`，就是在解引用一个指针：`rcx` 是地址，`[rcx]` 是那个地址处的内容。

理解指针是读反汇编的前提：**反汇编里的方括号 `[...]` 就是指针解引用**。

## 3. 函数调用：栈帧的建立与销毁

调用一个函数时，程序要在栈上做一套「建立 → 使用 → 销毁」的动作，这套动作用到的栈区域叫**栈帧（stack frame）**：

```c
int add(int a, int b) {
    int sum = a + b;   // sum 是局部变量，存在栈帧里
    return sum;
}
```

调用 `add(3, 5)` 时，栈上大致发生：

```text
调用前：把参数 3、5 准备好（放寄存器或压栈）
调用时：保存返回地址（函数返回后回到哪）
进入函数：建立栈帧，给局部变量 sum 留空间
函数体：在栈帧里读写 sum
返回时：销毁栈帧，按返回地址跳回调用处
```

这个过程在汇编层面的细节（哪些寄存器、怎么对齐），在[x64 汇编](../02-assembly/chapter-02-x64-assembly.md)里讲。这里先建立 C 语言层面的心智模型：**函数调用 = 参数 + 返回地址 + 局部变量 + 返回**。

## 4. 参数传递与返回值

函数调用涉及两件事：参数怎么传进去，返回值怎么传出来。

- **参数**：调用者把参数放到约定的位置（x64 上通常是寄存器，多了才压栈）。
- **返回值**：被调函数把结果放到约定的位置（x64 上通常是 `RAX`）。

不同的「约定」就是调用约定（calling convention）。C 语言层面你不需要关心细节，但逆向时，**看懂一个函数怎么收参数、怎么返回值，是理解函数功能的第一步**。

## 5. 为什么要先建立这些心智模型

这些 C 语言层面的概念，是读汇编的「预训练」：

- 看到栈上的读写 → 对应「局部变量」。
- 看到指针解引用 → 对应「访问某块内存」。
- 看到函数调用序列 → 对应「参数 + 返回」。

有了这些心智模型，读汇编时你就不是在看「一堆寄存器操作」，而是在看「一个 C 函数被翻译成了什么」。
