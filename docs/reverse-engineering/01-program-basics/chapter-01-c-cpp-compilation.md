# C/C++ 编译过程与优化

逆向是把「从源码到程序」的过程反过来。因此，逆向的第一步，是理解正向的过程：一段 C/C++ 源码，经过哪些步骤变成 CPU 执行的机器码。理解了编译，才能理解反编译出来的结果为什么长那样。

## 1. 为什么逆向要懂 C/C++

绝大多数需要逆向的程序——系统软件、游戏、商业应用、恶意软件——是用 C 或 C++ 写的。原因在于：

- **逆向的参照物**：你知道「源码长什么样、编译后会变成什么」，才有参照物去理解机器码在干什么。
- **反编译产物是类 C 代码**：反编译器的输出（伪代码）看起来就是 C 语言，不懂 C 就看不懂伪代码。
- **C++ 有额外的结构**：虚函数、RTTI、STL 容器，编译后会留下特征，理解这些特征需要懂 C++ 的内存模型。

## 2. 编译的四个阶段

一段 C 源码到可执行文件，经过四个阶段：

```text
预处理 → 编译 → 汇编 → 链接
```

| 阶段 | 做什么 | 产物 |
| :-- | :-- | :-- |
| 预处理 | 展开 `#include`、宏替换、条件编译 | 展开后的源码 |
| 编译 | 源码翻译成汇编 | `.s` 汇编文件 |
| 汇编 | 汇编翻译成机器码 | `.o` 目标文件 |
| 链接 | 合并目标文件、解析符号、生成可执行文件 | `.exe` |

对逆向而言，最重要的是**编译阶段**——它决定「源码变成什么汇编」。同一段源码，不同编译器（MSVC、GCC、Clang）、不同优化级别，生成的汇编差异很大。

## 3. 编译器优化

编译器默认会对代码做优化，这直接改变反汇编的结果。理解优化，才能解释「为什么源码里清晰的逻辑，反汇编里不见了」。

常见优化：

| 优化 | 源码 | 优化后的效果 |
| :-- | :-- | :-- |
| 常量折叠 | `int x = 2 + 3;` | 直接变成 `int x = 5;` |
| 死代码消除 | 永远不执行的 `if` 分支 | 分支被删掉 |
| 内联（inline） | 调用一个小函数 | 函数体直接展开，不再有 `call` |
| 循环展开 | `for (i=0;i<4;i++)` | 4 次循环体直接展开 |

这些优化意味着：**反汇编不一定能对应回「一行源码」**。一段清晰的源码，优化后可能被内联、重排、合并，甚至消失。这是反编译产物和源码「对不上」的根本原因。

一个关键提示：**用 `-O0`（关闭优化）编译的程序，反汇编最容易读**（接近源码结构）；用 `-O2` 优化的程序，反汇编更紧凑但更难读。练习逆向时，从 `-O0` 开始，逐步过渡到优化版本。

## 4. 链接

链接阶段把多个目标文件合并成可执行文件，核心工作是**符号解析**：一个目标文件里引用的函数（如 `printf`），要在其他目标文件或库文件里找到定义，把「符号引用」替换成「实际地址」。

链接分两种（前一阶段也提到）：

- **静态链接**：函数代码被复制进最终文件。
- **动态链接**：只记录「需要哪个 DLL 的哪个函数」，运行时解析。

Windows 程序几乎都动态链接系统 DLL，这就是 PE 导入表存在的原因。链接决定了「哪些函数在文件里、哪些函数要从 DLL 解析」，也决定了逆向时看到的是「自己的代码」还是「对系统函数的调用」。

## 5. 对逆向的启示

把编译过程理解透，逆向就有了方向感：

- **反编译产物是「翻译」，不是「复原」**：类型、变量名、注释这些信息在编译时丢了，反编译器只能猜。
- **优化改变了代码形态**：不要指望反汇编和源码一一对应，要理解「优化后的等价形式」。
- **链接决定了函数归属**：看到 `call`，先判断是「程序自己的函数」还是「导入的系统函数」。

## 6. 练习目标：贯穿全专题的一个程序

为了让你能「跟着一个真实目标」走完整个专题，这里准备一个贯穿全专题的练习程序 `crackme.c`。它覆盖了后续各阶段要用到的大部分知识点：函数、数组、循环、条件分支、字符串处理。

```c
#include <stdio.h>
#include <string.h>

int check_serial(const char* input) {
    unsigned char expected[] = {0x63, 0x5F, 0x52, 0x64,
                                0x43, 0x56, 0x54, 0x5C};
    int i = 0;
    while (input[i] && expected[i]) {
        if ((input[i] ^ 0x37) != expected[i])
            return 0;
        i++;
    }
    return input[i] == 0 && expected[i] == 0;
}

int main() {
    char buf[64];
    printf("Enter serial: ");
    fgets(buf, sizeof(buf), stdin);
    buf[strcspn(buf, "\n")] = 0;
    if (check_serial(buf))
        printf("Correct!\n");
    else
        printf("Wrong serial.\n");
    return 0;
}
```

编译它（MSVC 或 MinGW）：

```text
C:\> cl /O2 crackme.c
C:\> gcc -O2 -o crackme.exe crackme.c
```

先运行确认行为：输入任意字符串输出 `Wrong serial.`。这个程序后面会反复出现——[x64 汇编](../02-assembly/chapter-02-x64-assembly.md)用它的反汇编讲解指令，[静态分析](../05-static-analysis/chapter-01-basics.md)分析它的逻辑，[x64dbg](../06-dynamic-debugging/chapter-02-x64dbg.md)调试它的校验，最后[综合实战](../09-comprehensive-practice/chapter-01-crackme.md)完整还原出正确序列号。

> 建议现在就用一个 `-O0`（关闭优化）和一个 `-O2`（优化）版本各编译一份。后续对比两种优化级别下的反汇编差异，是理解「优化改变代码形态」最好的方式。
