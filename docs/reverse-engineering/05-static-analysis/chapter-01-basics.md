# 静态分析的方法与工具全景

前四篇铺好了地基，本文开始进入实践：拿到一个陌生的 Windows 可执行文件，不运行它，怎么一步步摸清它在干什么。本文讲静态分析的方法论和工具全景，是后续 IDA、Ghidra 上手操作的引子，不假设你会用任何特定工具，只讲该按什么顺序看、每一步能得到什么。

## 1. 反汇编和反编译，不是一回事

先澄清两个总被混用的词：

- **反汇编（disassembly）**：把机器码翻译成汇编指令。结果忠实于机器码，但仍是底层语言。
- **反编译（decompilation）**：把机器码进一步还原成类 C 的伪代码。结果更好读，但可能不精确、有猜测成分。

静态分析的日常工作，是在两者之间切换：**用反编译伪代码快速理解逻辑，用反汇编核对细节**。伪代码会骗人（比如错误推断类型、漏掉副作用），所以关键结论要回到反汇编里验证。这个「交叉验证」的习惯，比学会某个按钮重要得多。

## 2. 第一步：识别文件类型与架构

别急着扔进反汇编器。先回答几个基础问题：这是什么文件？多少位？什么架构？加壳了吗？

用**文件识别工具**先看一遍：

```text
C:\> file target.exe
target.exe: PE32+ executable (GUI) x86-64, for MS Windows
```

- `PE32+` 是 64 位，`PE32` 是 32 位；`x86-64` 是架构；`GUI` / `console` 是子系统（有无控制台窗口）。
- **Detect It Easy（DIE）** 是更专业的 PE 识别工具，还能判断编译器、是否加壳。这一行信息能立刻帮你决定后面用什么方法：32 位程序用 32 位工具，加壳的程序要先处理壳（[加壳与脱壳](../07-packing/chapter-01-packing-principle.md)）。

判断是否加壳的快速信号：节区名异常（如 `UPX0`、`UPX1`、`.packed`）、入口点落在非 `.text` 节、节区 `SizeOfRawData` 远小于 `VirtualSize`、DIE 直接报出壳名。看到这些，先别反汇编，去[加壳与脱壳](../07-packing/chapter-01-packing-principle.md)。

## 3. 第二步：看元信息与字符串

用 PE 查看工具（PE-bear、CFF Explorer，或微软自带的 `dumpbin`）打开文件，重点看：

- **节区列表**：有哪些节、权限如何，对程序结构有个印象。
- **导入表 / 导出表**：这是「程序想干什么」的第一线索（[PE 文件格式](../04-pe-format/chapter-02-address-and-tables.md)已讲）。

接着用**字符串提取**看程序里嵌的可读文本：

```text
C:\> strings target.exe
```

字符串常包含关键信息：URL、文件路径、注册表键、错误提示、加密算法名、密钥等。一个有 `https://...` 和 `POST` 的程序很可能要联网；出现 `license`、`trial` 字样的可能涉及授权逻辑。字符串分析成本极低，却常常直接给出突破口。

> `strings` 在 Linux/macOS 原生可用，Windows 上可用 Sysinternals 的 `strings.exe`，或直接在反汇编器里看字符串视图。不要用字符串内容替代真正的行为分析——它只是线索，不是结论。

## 4. 第三步：定位入口，找到真正的 main {#find-main}

PE 的 `AddressOfEntryPoint` 指向的是**真正入口点（entry point）**，但它通常不是 `main`。C/C++ 程序在 `main` 之前要跑一段运行时初始化（CRT 初始化、构造全局对象等），所以入口点先进入 CRT 代码，再由它调用 `main`。

要找到 `main`，方法有几种：

- 反汇编器通常会自动识别，把入口点函数标成 `start`，并提示哪里是 `main`。
- 从入口点函数往下追，找它 `call` 的那个被传入 `__argc`、`__argv` 的函数（x64 上 `main` 的参数是 `RCX`（argc）、`RDX`（argv））。
- 有符号（PDB）的程序，反汇编器直接显示函数名，`main` 一眼可见。

对逆向来说，**你真正要分析的是 `main` 及其调用的业务逻辑，而不是 CRT 初始化代码**。初学常犯的错，是盯着入口点的 CRT 代码看半天，其实那是每个程序都一样的模板。

## 5. 第四步：读反汇编 / 伪代码

定位到 `main` 后，开始真正的阅读。结合[x64 汇编](../02-assembly/chapter-02-x64-assembly.md)的知识，按这个节奏：

1. **先看函数级视图**：反汇编器会把函数列出来。扫一遍函数名（如果有符号）和大小，形成「这个程序由哪些函数组成」的印象。
2. **看导入函数调用**：在反汇编里找 `call <导入函数>`，反汇编器会标注名字。这是最快理解「程序在做哪类操作」的路径。
3. **用反编译器生成伪代码**：把 `main` 反编译成类 C 代码，逻辑立刻清晰很多。
4. **交叉引用（xref）**：对感兴趣的数据（如某个字符串）查「谁引用了它」，能反推程序的判断逻辑藏在哪。
5. **关键判断处核对反汇编**：伪代码里的 `if`、循环，回到反汇编看 `cmp + jcc`，确认没被反编译器误导。

[IDA Pro](./chapter-04-ida-pro.md) 和 [Ghidra](./chapter-05-ghidra.md) 会把这些动作落到具体操作上。

## 6. 工具全景：静态分析用哪些

静态分析工具按用途分层，从轻到重：

| 层 | 工具 | 用途 |
| :-- | :-- | :-- |
| 文件识别 | Detect It Easy、`file` | 判架构、判壳、判编译器 |
| 文件结构查看 | PE-bear、CFF Explorer、`dumpbin` | 看节区、导入导出、重定位 |
| 字符串提取 | `strings`、反汇编器内置 | 快速找线索 |
| 反汇编 | IDA Pro、Ghidra、Binary Ninja、objdump | 读机器码翻译 |
| 反编译 | IDA Pro（Hex-Rays）、Ghidra | 还原伪代码 |

其中 **IDA Pro** 和 **Ghidra** 是这一章的主角，两者的定位如下：

- **IDA Pro**：商业付费，交互体验、分析深度、脚本生态（IDAPython）和插件最成熟，是安全行业的实际标准。反编译器（Hex-Rays Decompiler）单独付费。当前主流版本为 8.x 和 9.x（见官方 [release notes](https://docs.hex-rays.com/release-notes/)）。
- **Ghidra**：NSA 开源免费，反编译能力很强，自带反编译器（这点对入门很友好，不用额外付费），支持多平台，还能写 Java/Python 脚本自动化分析。当前版本约 11.x～12.x（见官方 [release notes](https://ghidra-sre.org/)）。

**入门建议：用 Ghidra 起步，把方法学会；如果之后从事专业逆向工作，再上 IDA Pro。** 两者的核心概念（函数、交叉引用、反编译、命名重命名）几乎一一对应，学会一个，另一个上手很快。
