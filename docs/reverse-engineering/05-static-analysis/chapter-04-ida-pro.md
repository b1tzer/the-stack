# IDA Pro 静态分析实操

> 拿到一个没有源码的 `.exe`，你想知道它的校验逻辑藏在哪、正确密码是什么。IDA Pro 是把这段机器码还原成可读逻辑的行业标准工具。本文不讲 IDA 的全部功能，只讲完成一次静态分析必须会用的一组操作。

**前置条件**：已读 [PE 文件格式](../04-pe-format/chapter-01-pe-headers.md)、[x64 汇编](../02-assembly/chapter-02-x64-assembly.md) 和[静态分析基础](./chapter-01-basics.md)，电脑上安装了 IDA Pro（8.x 或 9.x，本文操作在两个大版本间通用）。分析一个你自己编写、有权分析的 Windows 程序练手效果最好。

## 1. 加载文件

启动 IDA，选择「New」（新建分析）并选中你的 `.exe`。IDA 会弹出加载对话框，其中两个选项需要注意：

- **Processor type**：保持自动识别（x64 程序会识别为 `metapc` 64 位）。
- **Load resources / 其他加载选项**：入门保持默认即可。

点 OK 后，IDA 自动反汇编并做一轮分析，几秒到几十秒后进入主界面。**如果 IDA 报「架构识别错误」或加载成 32 位，多半是这个文件本身是 32 位或已被损坏**——先用 Detect It Easy 确认架构（[静态分析基础](./chapter-01-basics.md)第 2 节）。

分析完成后，先把数据库存下来：`File → Save`。IDA 会把分析结果存进一个 `.i64`（64 位）或 `.idb`（32 位）数据库文件，下次直接打开数据库即可，无需重新分析。

## 2. 认识主界面

IDA 默认打开几个窗口，你只需要先认识其中四个：

| 窗口 | 快捷键 | 作用 |
| :-- | :-- | :-- |
| **IDA View**（反汇编视图） | `Esc` 返回 | 显示当前地址的反汇编，最核心的窗口 |
| **Functions**（函数窗口） | 无（可在 View 菜单打开） | 列出所有已识别函数 |
| **Strings**（字符串窗口） | `Shift+F12` | 列出程序里的字符串 |
| **Imports**（导入表窗口） | 无（View → Open subviews） | 列出导入函数 |

在反汇编视图里，`Space` 键在**图形视图**和**文本视图**之间切换。图形视图把函数画成带箭头的控制流图，更适合看整体；文本视图是逐行的汇编列表，更适合精读。入门建议先在图形视图里看懂结构。

## 3. 定位到 main

加载后 IDA 通常停在入口点（entry point），那里是 CRT 初始化代码，不是你要分析的逻辑。找到 `main` 的常用办法：

1. 在 **Functions 窗口**里搜 `main`（有符号的程序直接有这个名字）。
2. 如果没有符号，跳到入口点（`G` 输入 `start` 或入口点地址），往下找被 `call` 且以 `RCX`（argc）`RDX`（argv）传参的函数。

找到 `main` 后，双击进入它，按 `Space` 切到图形视图，你会看到一个清晰的函数结构。**如果图形视图里函数边界混乱、指令全是 `db`（数据字节），说明 IDA 没正确识别函数**——把光标放在函数起点按 `P`（创建函数）即可修正。

## 4. 看懂逻辑：反编译 + 交叉引用 {#decompile-xref}

这是静态分析的核心循环，重复四步：

**第一步，读伪代码。** 光标停在函数内，按 `F5`，IDA 会弹出 Hex-Rays 反编译窗口，把汇编还原成类 C 代码。立刻就能看懂 `if`、循环和函数调用。

**第二步，看导入函数调用。** 在伪代码或反汇编里，导入函数会直接显示名字（如 `CreateFileW`、`WriteFile`）。看到这些调用，你就能判断这段代码在做什么操作。

**第三步，查交叉引用。** 对任何感兴趣的对象——一个字符串、一个函数、一个数据——把光标放上去按 `X`，IDA 列出「谁引用了它」以及引用位置。这是反推「某个字符串在哪个判断逻辑里被使用」的关键操作。例如看到字符串 `"Wrong password"`，按 `X` 找到引用它的代码，往上读就是密码校验逻辑。

**第四步，回到反汇编核对。** 伪代码可能误判类型或漏掉细节，关键判断处按 `Tab` 或点回反汇编视图，看 `cmp + jcc` 确认逻辑真实成立。

这四个步骤循环进行，直到你复述出程序的核心行为。下面是一个浓缩的例子。

## 5. 一个完整示例：分析密码校验

假设你有一个自编的 `check.exe`，逻辑是「输入密码，正确则打印成功」。用 IDA 分析它的过程如下：

1. 加载后，`Shift+F12` 打开字符串窗口，看到两个关键字符串：`"Correct!"` 和 `"Wrong password"`。
2. 双击 `"Wrong password"`，跳到它所在的数据位置；光标放上去按 `X`，看到只有一处引用，双击跳到引用它的代码。
3. 该处代码是一段比较逻辑，`F5` 反编译后形如：

```c
if (strcmp(input, "secret123") == 0) {
    puts("Correct!");
} else {
    puts("Wrong password");
}
```

4. 回到反汇编核对：`strcmp` 的参数、`cmp eax, 0` 后接 `jne` 的分支，与伪代码一致。

到这一步，你已经在**不运行程序**的情况下，还原出了校验逻辑和正确密码。这就是静态分析的一个完整闭环。

## 6. 常用操作速查

把这一篇用到、以及下一阶段会用到的高频操作集中列在这里：

| 操作 | 快捷键 / 方式 |
| :-- | :-- |
| 跳转到地址 | `G` |
| 重命名（函数/变量/数据） | `N` |
| 查交叉引用 | `X` |
| 反编译为伪代码 | `F5` |
| 图形 / 文本视图切换 | `Space` |
| 字符串窗口 | `Shift+F12` |
| 加注释 | `;`（普通注释）、`:`（可重复注释） |
| 修改变量/函数类型 | `Y` |
| 创建函数 | `P` |
| 撤销一次分析（把代码还原成数据） | `U` |
| 保存数据库 | `Ctrl+S` |

其中 **重命名（`N`）** 值得单独强调：反汇编出来的函数和变量都是无意义的名字（`sub_140001000`、`v1`）。每当你搞懂一个函数或变量在做什么，立刻按 `N` 给它起一个有意义的名字。这样随着分析推进，反汇编会越来越「自解释」，这是 IDA 工作流的核心习惯。

## 7. 失败与回退

- **IDA 识别不出函数**：入口或某段代码显示成 `db` 数据 → 光标定位后按 `P` 创建函数；反之若一段数据被误当成代码，按 `U` 还原。
- **反编译结果明显不对**（如大量 `unknown`、错误的循环）→ 通常是分析信息不足，先 `N` 重命名、`Y` 修正参数类型，再 `F5` 重试。
- **加载时架构选错** → `File → New` 重新加载，注意 Processor type；或先确认文件位数。

IDA 的界面和快捷键在 8.x / 9.x 间保持稳定，本文操作在两个大版本都适用。
