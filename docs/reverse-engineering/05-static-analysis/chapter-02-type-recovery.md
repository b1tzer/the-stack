# 类型恢复与结构体识别

反编译产物里，类型信息大量缺失——机器码里没有「这是结构体、那是数组、这个变量是 int」这些标注。反编译器只能把未知数据标成 `unk`、`void*`。这一章讲如何从反汇编里**把类型和结构体恢复回来**，让伪代码从「一坨指针」变成「可读的 C 代码」。

## 1. 为什么需要类型恢复

编译时，类型信息大多被丢掉：`int`、`char*`、`struct Point` 在机器码里都只是一段内存和一套操作。反编译器面对一段内存，只知道「这里被读写了 4 字节」，不知道它是什么。

类型恢复的目标，是**通过观察「这段内存怎么被使用」，反推它是什么类型**。使用方式会留下线索：读写宽度、访问偏移、参与什么运算、传给什么函数。

## 2. 从访问偏移恢复结构体

结构体的成员，编译后是「基址 + 固定偏移」的访问。观察这些偏移，就能拼出结构体布局：

```asm
mov  [rcx],   eax    ; 偏移 0，4 字节
mov  [rcx+4], edx    ; 偏移 4，4 字节
mov  [rcx+8], r8d    ; 偏移 8，4 字节
```

这段代码往 `rcx` 指向的内存写了三个 4 字节，偏移分别是 0、4、8。结合上下文，可以推断 `rcx` 指向一个含三个 `int` 字段的结构体，反推成：

```c
struct { int a; int b; int c; };
```

**方法**：收集所有「基址 + 偏移」的访问，按偏移分组，同一偏移、同宽度的访问对应同一个成员。偏移 0 是第一个成员，偏移 4 是第二个，以此类推。

## 3. 从索引缩放恢复数组

数组访问的特征是「基址 + 索引 × 元素大小」：

```asm
mov  eax, [rdx+rax*4]   ; 元素 4 字节
mov  ecx, [rdx+rax*8]   ; 元素 8 字节
```

`×4` 说明是 4 字节元素（`int`、`float`、指针），`×8` 是 8 字节元素（`long`、`double`、指针）。结合「谁在当索引、循环怎么走」，能还原出数组的类型和维度。

## 4. 从调用约定恢复参数

函数的参数个数和类型，也能从调用处反推：

- **参数个数**：x64 下，前 4 个参数走 `RCX/RDX/R8/R9`，看调用前设置了哪几个寄存器，就知道传了几个参数。
- **参数类型**：看参数被怎么用——作为指针解引用、作为整数比较、还是传给别的函数。
- **返回值**：看 `RAX` 返回后被怎么用。

例如，一段代码 `lea rcx, [str]; call foo`，说明 `foo` 的第一个参数是个指针（`rcx` 里放的是地址）。

## 5. 控制流与数据流分析

类型恢复依赖两条分析线：

- **控制流分析**：理解程序的分支、循环结构，这是识别「这段代码在做什么」的基础。
- **数据流分析**：追踪一个值从哪来、到哪去、被怎么变换。追踪一个「从 `malloc` 返回、被写入若干字段、再传给某函数」的值，就能还原出它的结构。

反汇编器和反编译器会做一部分自动分析，但关键的「这是什么类型」仍需要人工判断。这正是逆向的价值所在。

## 6. 工具操作：定义结构体

IDA 和 Ghidra 都支持手动定义结构体，然后应用到变量上：

- 在 IDA 里，`Shift+F1` 打开结构体窗口，定义结构体；对变量按 `T` 应用结构体类型。
- 在 Ghidra 里，Data Type Manager 里定义结构体，右键变量设置类型。

定义结构体后，反编译产物会从 `*(int*)(ptr+4)` 变成 `ptr->field2`，可读性大幅提升。**「边分析边定义类型」是逆向的核心工作流**，和「边分析边重命名」一样重要。
