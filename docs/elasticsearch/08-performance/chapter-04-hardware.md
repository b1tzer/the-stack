# 硬件选型

## 1. 硬件需求概述

| 资源 | 需求等级 | 说明 |
| :-- | :-- | :-- |
| **内存** | ⭐⭐⭐⭐⭐ | 最重要，影响查询性能和缓存 |
| **磁盘 IO** | ⭐⭐⭐⭐ | 影响写入和查询速度 |
| **CPU** | ⭐⭐⭐ | 影响聚合和排序性能 |
| **网络** | ⭐⭐ | 影响集群通信和数据迁移 |

## 2. 存储选型

| 类型 | 适用场景 | IOPS | 成本 |
| :-- | :-- | :-- | :-- |
| **NVMe SSD** | Hot 节点、搜索密集 | 100K+ | 高 |
| **SATA SSD** | Hot/Warm 节点 | 10K~50K | 中 |
| **HDD** | Warm/Cold 节点 | 100~200 | 低 |
| **云盘 (gp3)** | 云环境通用 | 可配置 | 中 |

```yaml
# Hot 节点（SSD）
path.data: /data/ssd1,/data/ssd2

# Warm 节点（HDD）
path.data: /data/hdd1,/data/hdd2
```

## 3. 内存配置

| 场景 | 内存建议 | 说明 |
| :-- | :-- | :-- |
| 小型集群 | 16~32GB | 堆 8~16GB |
| 中型集群 | 64~128GB | 堆 16~31GB |
| 大型集群 | 128~256GB | 堆 31GB + 大量 OS 缓存 |

> **核心原则**：堆内存不超过物理内存的 50%，留给文件系统缓存。

## 4. CPU 选型

| 场景 | CPU 建议 |
| :-- | :-- |
| 搜索密集 | 高主频（3.0GHz+），核心数适中 |
| 聚合密集 | 多核心（16+），主频适中 |
| 写入密集 | 多核心 + 高主频 |
| 通用场景 | 8~16 核，2.5GHz+ |

## 5. 网络配置

| 配置 | 建议 |
| :-- | :-- |
| 带宽 | ≥ 10Gbps（生产环境） |
| 延迟 | < 1ms（同机房） |
| 节点间通信 | 同一机房/可用区 |

## 6. 云环境配置

### 6.1 AWS 推荐

| 节点类型 | 实例类型 | 存储 |
| :-- | :-- | :-- |
| Hot Data | r6i.xlarge | gp3 SSD |
| Warm Data | r6i.xlarge | st1 HDD |
| Master | m6i.large | gp3 |

### 6.2 阿里云推荐

| 节叶类型 | 实例类型 | 存储 |
| :-- | :-- | :-- |
| Hot Data | ecs.r6.xlarge | ESSD PL1 |
| Warm Data | ecs.r6.xlarge | 高效云盘 |
| Master | ecs.g6.large | ESSD PL1 |

## 7. 硬件配置示例

```yaml
# Hot 节点（搜索/写入密集）
CPU: 16 核 (3.0GHz+)
内存: 64GB（堆 31GB）
存储: 2TB NVMe SSD
网络: 10Gbps

# Warm 节点（数据存储）
CPU: 8 核
内存: 32GB（堆 16GB）
存储: 8TB HDD
网络: 10Gbps

# Master 节点（集群管理）
CPU: 4 核
内存: 8GB（堆 4GB）
存储: 100GB SSD
网络: 1Gbps
```

## 8. 最佳实践

- Hot 节点使用 SSD，Warm/Cold 节点可使用 HDD
- 堆内存不超过物理内存的 50%，不超过 32GB
- 留足够内存给文件系统缓存
- 生产环境网络带宽 ≥ 10Gbps
- 使用 `memory_lock` 防止 swap
- 多路径数据目录分散 IO 压力
- 定期监控硬件资源使用率
