# 集群架构

> ES 是分布式搜索引擎，理解集群、节点、分片的关系是运维 ES 的基础。

## 1. 集群组成

```text
┌──────────────────────────────────────────────────┐
│                  ES Cluster                       │
│                                                  │
│  ┌─────────────┐ ┌─────────────┐ ┌─────────────┐│
│  │  Node 1     │ │  Node 2     │ │  Node 3     ││
│  │  master     │ │  data_hot   │ │  data_hot   ││
│  │  data       │ │             │ │             ││
│  │             │ │  Shard P1   │ │  Shard P2   ││
│  │  Shard R2   │ │  Shard R3   │ │  Shard R1   ││
│  └─────────────┘ └─────────────┘ └─────────────┘│
└──────────────────────────────────────────────────┘
```

## 2. 节点角色

| 角色 | 说明 | 推荐 |
|------|------|------|
| master | 管理集群状态（索引创建/删除、分片分配） | 专用，不存数据 |
| data_hot | 热数据节点，SSD | 存储最近数据 |
| data_warm | 温数据节点，HDD | 存储历史数据 |
| data_cold | 冷数据节点，对象存储 | 存档数据 |
| ingest | 预处理节点 | 数据预处理 |
| coordinating | 协调节点 | 请求路由和结果合并 |

## 3. 分片（Shard）

```text
Index: orders
  ├── Shard 0 (Primary → Node 1, Replica → Node 2)
  ├── Shard 1 (Primary → Node 2, Replica → Node 3)
  └── Shard 2 (Primary → Node 3, Replica → Node 1)
```

- **Primary Shard**：数据的主副本，处理写入
- **Replica Shard**：Primary 的副本，提供读取冗余和高可用
- 分片数在索引创建时指定，**创建后不能修改**
- 副本数可以动态修改

## 4. 分片数选择

| 数据量 | 推荐分片数 | 说明 |
|--------|-----------|------|
| < 1GB | 1 | 单分片足够 |
| 1-10GB | 3-5 | 均衡查询和写入性能 |
| 10-100GB | 5-10 | 需要并行查询 |
| > 100GB | 按需增加 | 每个分片 10-50GB 为宜 |

**经验法则**：每个分片 10-50GB。分片太多会增加集群管理开销。

## 5. 集群健康状态

| 颜色 | 含义 | 原因 |
|------|------|------|
| green | 所有分片正常 | - |
| yellow | 副本分片未分配 | 副本数 > 可用节点数 |
| red | 主分片未分配 | 节点故障、磁盘满 |

GET /_cluster/health
