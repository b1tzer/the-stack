# 对象的内存真相

本页面向已经理解"一切皆对象"的读者，回答一个问题：一个 Python 对象在内存里到底长什么样、占多少字节。前置知识是语言核心[引用与对象模型](../01-python-language/chapter-07-references-and-objects.md)。

示例基于 CPython 3.13+，64 位平台；具体字节数随版本和平台变化，实验以你本机输出为准。

## 1. PyObject：所有对象的共同开头

在 CPython 的 C 源码里，每个 Python 对象的内存都从一个共同的结构开始，它至少包含两个字段：

```txt
┌──────────────────────┐
│  ob_refcnt（引用计数） │   ← 有几个名字指向这个对象
├──────────────────────┤
│  ob_type（类型指针）   │   ← 指向这个对象的类型对象
└──────────────────────┘
```

`ob_refcnt` 是引用计数，记录当前有多少个名字/容器指向这个对象；`ob_type` 指向描述"这个对象是什么类型"的类型对象。这两个字段是所有对象都有的公共头部，之后才是各类型自己的数据。

用 `sys.getrefcount` 可以观察引用计数：

```python
import sys
a = []
sys.getrefcount(a)   # 2：a 本身 + 传给 getrefcount 的参数
```

`getrefcount` 自己也会临时增加一次引用，所以返回值通常比你的直觉多 1。

## 2. 不同类型的内存布局

公共头部之后，各类型携带自己的数据。几种常见类型：

- **int**：在头部之外存数字的值，而且数字越大占的位数越多——这正是"任意精度整数"的代价：不像固定 64 位，Python 整数按需分配空间。
- **str**：存字符编码后的字节，还有长度、哈希缓存等字段。
- **list**：存一个指向"对象指针数组"的指针、已用长度和预分配容量。列表里存的其实是**指针**，不是对象本身。
- **dict**：存一个哈希表，有键值对数组、容量、已用数等字段。

用 `sys.getsizeof` 看一个对象本身占多少字节（不含它引用的子对象）：

```python
import sys
sys.getsizeof(1)        # 28（CPython 3.13，64 位）
sys.getsizeof('')       # 49
sys.getsizeof([])       # 56
sys.getsizeof({})       # 64
```

注意 `getsizeof` 只算对象自身，列表里元素占的内存不算在内——这也是它常被误解的地方。

## 3. 小整数缓存

Python 启动时预先创建了一批小整数对象（-5 到 256），之后用到这些数时直接复用同一个对象，不再新建：

```python
a = 100
b = 100
a is b   # True  复用缓存里同一个整数对象

c = 1000
d = 1000
c is d   # False  超出缓存范围，各自新建
```

`-5` 到 `256` 是最常用的整数（循环下标、计数、状态码），预先缓存能省大量分配。这也是"不要用 `is` 比较整数"的原因——小整数恰好 `is` 成立，大整数又不成立，行为不可依赖。

## 4. 字符串驻留

类似地，某些字符串会被"驻留"（intern）：相同的字符串复用同一个对象。编译期出现的字符串字面量、标识符、以及用 `sys.intern` 显式驻留的字符串，都会共享：

```python
a = 'hello'
b = 'hello'
a is b   # True  两个字面量指向同一个驻留字符串

import sys
c = sys.intern('x' * 10)
d = sys.intern('x' * 10)
c is d   # True
```

驻留的意义是省内存、加速比较（`is` 比逐字符比较快）。但不要依赖它——哪些字符串会被驻留是解释器的实现细节。

## 5. 动手实验

**实验 1：观察引用计数变化**

```python
import sys
a = []
b = a
print(sys.getrefcount(a))   # 3：a、b、参数各一次
del b
print(sys.getrefcount(a))   # 2
```

**实验 2：对比对象自身大小**

```python
import sys
for obj in [0, 1, 2**64, '', 'hello', [], [1, 2, 3], {}, {'a': 1}]:
    print(type(obj).__name__, sys.getsizeof(obj))
```

观察：大整数比小整数占更多；列表有额外容量；字典比列表更"重"。

**实验 3：小整数缓存边界**

```python
for n in [256, 257]:
    a = n; b = n
    print(n, a is b)   # 256 True，257 False
```

## 6. 这一章要记住的结论

每个 Python 对象都以"引用计数 + 类型指针"的公共头部开头，之后才是类型各自的数据。列表存指针、字典存哈希表、整数按大小分配。小整数（-5~256）和部分字符串会被缓存/驻留共享同一个对象。`sys.getsizeof` 只看对象自身大小，`sys.getrefcount` 看引用计数（结果要减 1）。
