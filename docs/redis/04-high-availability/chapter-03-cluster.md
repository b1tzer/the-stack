# 集群模式

> 哨兵解决了高可用，但数据量大到单机装不下时，就需要把数据分片到多个节点。Redis Cluster 通过哈希槽把数据分散到多个主节点，同时支持水平扩展与自动故障转移。本章讲解集群的分片原理、请求路由与选型。

## 1. 分片原理

Redis Cluster 把整个键空间划分为 **16384 个哈希槽（slot）**，每个节点负责一部分槽，数据按 key 映射到槽。

### 1.1 槽的分配

```text
节点 A：负责 slot 0 ~ 5460
节点 B：负责 slot 5461 ~ 10922
节点 C：负责 slot 10923 ~ 16383
```

### 1.2 key 到槽的映射

```text
槽号 = CRC16(key) % 16384
```

- 对 key 计算 CRC16 校验和，再对 16384 取模
- 得到 0~16383 范围内的槽号

### 1.3 为什么是 16384

| 原因 | 说明 |
| :-- | :-- |
| 心跳包大小 | 节点间 Gossip 心跳携带槽信息，16384 个槽刚好用 2KB 表示 |
| 节点数上限 | 官方建议节点数 ~1000，16384 个槽足够分配 |
| 网络开销 | 槽数量过大时心跳包更大，节点通信开销增加 |

## 2. 集群架构

集群由多个「主节点 + 从节点」组成，每个主节点负责一部分槽，从节点作为主节点的副本。

![Redis Cluster 分片架构](/redis/04-high-availability-chapter-03-cluster.svg)

节点之间通过 **Gossip 协议**互相通信，交换集群状态、槽分配、节点健康信息。

## 3. MOVED 与 ASK 重定向

当客户端请求的 key 不在当前节点时，节点会返回重定向响应。

### 3.1 MOVED（永久重定向）

节点计算出 key 属于其他节点时，返回 `MOVED` 错误，告诉客户端去正确的节点：

```text
客户端 → 节点A：GET user:1001
节点A  → 客户端：-MOVED 12345 节点B的地址   （key 在节点 B）
客户端 → 节点B：GET user:1001（重新请求）
```

`MOVED` 是永久重定向，智能客户端会缓存槽与节点的映射，下次直接请求正确节点。

### 3.2 ASK（临时重定向）

集群扩容/缩容、槽迁移期间，key 可能正在从旧节点迁往新节点，此时返回 `ASK`：

```text
客户端 → 节点A：GET user:1001
节点A  → 客户端：-ASK 12345 节点B的地址   （槽正在迁移）
客户端 → 节点B：ASKING + GET user:1001   （临时访问迁移中的 key）
```

| 类型 | 场景 | 客户端行为 |
| :-- | :-- | :-- |
| MOVED | 槽已归属其他节点 | 更新本地映射，永久改道 |
| ASK | 槽正在迁移 | 临时访问一次，不更新映射 |

## 4. 跨槽与哈希标签

### 4.1 跨槽问题

集群下，多 key 命令（如 `MGET`、事务、Lua）要求所有 key 在同一个槽，否则报错。因为不同 key 可能分散在不同节点，无法保证原子性。

### 4.2 哈希标签

哈希标签（hash tag）强制多个 key 落到同一个槽——只对 `{}` 内的内容计算哈希：

```text
{user:1001}:name   → 只对 "user:1001" 计算槽
{user:1001}:age    → 只对 "user:1001" 计算槽
两者槽号相同，可用 MGET 一起操作
```

```bash
MGET {user:1001}:name {user:1001}:age   # 合法，同一槽
```

要点：

| 要点 | 说明 |
| :-- | :-- |
| 哈希标签 | `{}` 内的内容决定槽号 |
| 强制同槽 | 相关 key 用相同 hash tag 保证同槽 |
| 副作用 | 过度使用会导致数据倾斜 |

## 5. 三种方案选型

| 维度 | 主从 | 哨兵 | 集群 |
| :-- | :-- | :-- | :-- |
| 数据分片 | 否 | 否 | 是 |
| 自动故障转移 | 否 | 是 | 是 |
| 水平扩展 | 否 | 否 | 是 |
| 读写分离 | 是 | 是 | 支持（从节点读） |
| 实现复杂度 | 低 | 中 | 高 |

选型建议：

| 场景 | 推荐方案 |
| :-- | :-- |
| 数据量小、单机可装下、可接受手动切换 | 主从 |
| 数据量小、要求高可用 | 哨兵 |
| 数据量大、需要水平扩展 | 集群 |
