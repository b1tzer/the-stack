# 过期删除

> 缓存数据往往有生命周期，过期后需要及时删除以释放内存。Redis 用「惰性删除 + 定期删除」两条策略配合，在内存占用与 CPU 开销之间取得平衡。本章讲解过期键的存储与删除机制。

## 1. 过期键存储

Redis 为设置了 TTL 的键维护一个独立的过期字典，专门记录键的过期时间。

```text
expires 字典（独立的哈希表）
  "session:abc"  →  1712500000000（毫秒时间戳）
  "cache:order"  →  1712500360000
  ...
```

设置过期时间的命令：

```bash
EXPIRE key 300          # 300 秒后过期
PEXPIRE key 300000      # 300000 毫秒后过期
SET key value EX 300    # 设置时直接指定过期时间
TTL key                 # 查看剩余时间（秒）
PERSIST key             # 移除过期时间，永久保留
```

关键设计：过期时间单独存放在 `expires` 字典里，与主数据字典分离。这样查找某个键是否过期，只需查 `expires` 字典，O(1)。

## 2. 惰性删除

惰性删除指「访问时才发现过期、才删除」——键过期后不主动清理，等客户端访问这个键时检查并删除。

![惰性删除流程](/redis/02-standalone-core-chapter-05-expiration-1.svg)

特点：

| 维度 | 说明 |
| :-- | :-- |
| 优点 | 只在访问时检查，不额外消耗 CPU |
| 缺点 | 过期键长期不被访问就一直占内存 |
| 适用 | 作为补充策略，处理「访问到的过期键」 |

## 3. 定期删除

定期删除指「定时主动扫描并删除一批过期键」——每隔一段时间随机抽取一些键，删除其中已过期的。

### 3.1 执行机制

Redis 默认每 100 毫秒执行一次定期删除：

```text
每次执行：
1. 从 expires 字典随机抽取 20 个键
2. 删除其中已过期的键
3. 若已过期键占比 > 25%，重复步骤 1~2（继续这一轮）
4. 否则本轮结束，等待下一次
```

关键参数：

| 参数 | 含义 |
| :-- | :-- |
| 20 个 | 每次随机抽取的键数量 |
| 25% | 过期占比阈值，超过则继续扫描 |
| 100ms | 执行周期 |

特点：

| 维度 | 说明 |
| :-- | :-- |
| 优点 | 主动清理，避免过期键长期堆积 |
| 缺点 | 随机抽取，可能漏掉部分过期键 |
| 时间上限 | 单次执行有 CPU 时间上限，防止阻塞主线程 |

## 4. 两种策略的配合

惰性删除与定期删除是互补的：

![惰性删除与定期删除配合](/redis/02-standalone-core-chapter-05-expiration-2.svg)

- **定期删除**负责「主动」清理大部分过期键，控制内存
- **惰性删除**负责「被动」清理被访问到的过期键，保证返回正确

两者结合，既避免「过期键长期占内存」（纯惰性的缺点），又避免「扫描开销过大阻塞服务」（纯定期的缺点）。

> 即使有这两种策略，仍可能有少量过期键暂时留在内存里。当内存紧张时，就会触发内存淘汰策略（见第 6 章）来兜底。
