# 命令执行与 RESP

> 一条 `SET key value` 从客户端发出到 Redis 返回 `OK`，中间经历了协议编码、网络传输、协议解析、命令查找、执行、响应写回。理解这条链路，才能解释命令是如何被可靠、高效地执行的。

## 1. RESP 协议

RESP（REdis Serialization Protocol）是客户端与 Redis 通信的协议。它简单、易解析、二进制安全。

### 1.1 五种数据类型

| 类型 | 首字节 | 含义 | 示例 |
| :-- | :-- | :-- | :-- |
| 简单字符串 | `+` | 简单回复 | `+OK` |
| 错误 | `-` | 错误信息 | `-ERR unknown command` |
| 整数 | `:` | 整数回复 | `:1000` |
| 批量字符串 | `$` | 二进制安全的字符串 | `$3\r\nfoo\r\n` |
| 数组 | `*` | 多个元素 | `*2\r\n$3\r\nfoo\r\n$3\r\nbar\r\n` |

### 1.2 命令编码格式

客户端把命令编码为「数组 + 批量字符串」的格式发给 Redis：

```text
客户端发送：SET mykey myvalue
实际字节流：*3\r\n$3\r\nSET\r\n$5\r\nmykey\r\n$7\r\nmyvalue\r\n
             ↑        ↑            ↑
             数组3     SET(长度3)    mykey(长度5)  myvalue(长度7)
```

- `*3`：这是一个包含 3 个元素的数组
- `$3\r\nSET\r\n`：第一个元素是长度 3 的字符串 "SET"
- 依次类推

### 1.3 内联命令

除了 RESP 格式，Redis 也支持内联命令（空格分隔的纯文本），例如直接发送 `PING`。这只用于 telnet 等手工调试场景，客户端库一般都用 RESP 格式。

## 2. 命令解析

Redis 收到网络字节流后，需要把它解析成内部可执行的命令结构。

解析流程：

![RESP 命令解析流程](/redis/02-standalone-core-chapter-02-command-resp-1.svg)

解析的关键点：

| 环节 | 说明 |
| :-- | :-- |
| 读缓冲区 | 客户端连接有一个输入缓冲区，读到的字节先暂存于此 |
| 协议判断 | 首字节是 `*` 走 RESP 多批量命令解析，否则走内联命令解析 |
| 参数数组 | 解析出 `argv`（参数数组）与 `argc`（参数个数） |
| 二进制安全 | 批量字符串按 `$长度` 精确读取，不依赖 `\0` 结尾 |

## 3. 命令表查找

解析出命令名后，Redis 需要找到对应的命令实现。它维护一个命令表——所有命令的哈希表。

```text
命令表（哈希表，O(1) 查找）
  "SET"   → redisCommand { 实现函数, 参数个数, 属性标志 }
  "GET"   → redisCommand { ... }
  "HSET"  → redisCommand { ... }
  ...
```

`redisCommand` 结构的关键字段：

| 字段 | 作用 |
| :-- | :-- |
| 实现函数指针 | 指向真正执行命令的 C 函数 |
| arity | 参数个数，正数=精确，负数=最小参数数 |
| flags | 命令属性（写命令/只读命令/管理命令等） |

查找特点：

- **O(1) 哈希查找**：命令名作为 key，哈希表直接命中
- **大小写不敏感**：命令名统一转小写后查找，`SET` 与 `set` 等价
- **未知命令报错**：找不到返回 `-ERR unknown command`

## 4. 执行流程与钩子

找到命令后，执行过程会经过一系列钩子（Hook），这些钩子承载了 Redis 的很多附加能力。

![命令执行流程](/redis/02-standalone-core-chapter-02-command-resp-2.svg)

执行流程各环节：

| 环节 | 说明 |
| :-- | :-- |
| 参数校验 | 检查参数个数是否符合 arity 要求 |
| 键过期检查 | 惰性删除：访问到已过期 Key 时先删除再执行 |
| 执行命令 | 调用命令对应的实现函数，操作数据结构 |
| 慢查询日志 | 记录执行耗时超过阈值的命令 |
| AOF 传播 | 写命令追加到 AOF 缓冲区（见第 4 章） |
| 复制传播 | 写命令同步给从库（见第四卷） |
| 返回响应 | 把结果编码为 RESP 格式写回客户端 |

> 钩子机制的价值：Redis 把「持久化」「复制」等能力通过钩子挂在命令执行链路上，任何写命令都会自动触发 AOF 追加与主从传播，无需命令实现自己操心。这是 Redis 架构简洁的关键设计之一。
