# RDB 持久化

> RDB 是 Redis 的快照持久化方式：在某个时间点将内存数据dump到磁盘。

## 1. RDB 的工作原理

```text
Redis 内存数据
  → fork() 子进程（COW 机制）
  → 子进程将数据序列化为二进制格式
  → 写入 dump.rdb 文件
  → 替换旧的 dump.rdb
```

### fork() 与 COW（Copy-On-Write）

```text
父进程（继续处理请求）
  │
  ├─ fork() → 子进程（负责 dump）
  │
  ├─ 子进程看到的是 fork 时刻的内存快照
  ├─ 父进程继续写入 → 触发 COW → 修改的页被复制
  └─ 子进程不会看到父进程的新写入
```

## 2. 触发方式

```bash
# 配置触发条件
save 3600 1      # 3600秒内至少1个key变更
save 300 100     # 300秒内至少100个key变更
save 60 10000    # 60秒内至少10000个key变更

# 手动触发
SAVE       # 阻塞主线程（生产禁用）
BGSAVE     # 后台fork子进程
```

## 3. RDB 文件结构

```text
┌────────────────────────────────────────────┐
│ REDIS           (5字节魔数)                 │
│ rdb_version     (4字节版本号)               │
├────────────────────────────────────────────┤
│ AUX 字段         (Redis版本、创建时间等)    │
├────────────────────────────────────────────┤
│ SELECTDB        (数据库编号)               │
│ RESIZEDB        (哈希表大小)               │
│ key-value 对    (序列化的键值对)            │
│ ...                                        │
├────────────────────────────────────────────┤
│ EOF             (结束标记)                 │
│ check_sum       (校验和)                   │
└────────────────────────────────────────────┘
```

## 4. 优缺点

| 优点 | 缺点 |
|------|------|
| 文件紧凑，适合备份 | fork() 可能阻塞（大数据量） |
| 恢复速度快 | 两次快照之间的数据可能丢失 |
| 适合灾备 | 大内存 fork 开销大 |

## 5. fork() 阻塞问题

```text
Redis 内存 10GB → fork() 需要复制页表 → 耗时可能达数百毫秒
  → 这期间 Redis 无法处理请求

解决方案：
  1. 控制 Redis 实例内存（< 10GB）
  2. 使用 Linux 大页内存（Transparent Huge Pages）
  3. 在从库做 RDB，主库不做
```

## 6. 配置建议

```bash
# 生产环境
save 3600 1
save 300 100
dbfilename dump.rdb
dir /var/lib/redis
rdbcompression yes
rdbchecksum yes
```
