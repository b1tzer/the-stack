# 开发运维陷阱

> Redis 踩坑大多来自「命令误用」与「配置不当」。本章汇总开发、运维、集群三方面的常见陷阱，并提供上线前检查清单。

## 1. 开发陷阱

| 陷阱 | 问题 | 正确做法 |
| :-- | :-- | :-- |
| `KEYS *` | 全量遍历阻塞主线程 | 用 `SCAN` 游标分批 |
| `DEL` 大 Key | 同步删除阻塞 | 用 `UNLINK` 异步删除 |
| `HGETALL` 大 Hash | 一次返回全部字段 | 用 `HSCAN` 分批 |
| String 存整块 JSON | 更新需全量覆盖 | 用 Hash 存字段 |
| 无 TTL 缓存 | key 永久堆积 | 设置合理 TTL |
| 短连接 | 反复 TCP 握手 | 使用连接池 + 长连接 |

## 2. 运维陷阱

| 陷阱 | 问题 | 正确做法 |
| :-- | :-- | :-- |
| 主节点不持久化 | 主从切换后数据丢失 | 主节点必须开持久化 |
| 不设 maxmemory | 内存涨到 OOM | 设上限 + 淘汰策略 |
| 内存超物理上限 | 触发 swap，性能骤降 | 预留内存余量 |
| 透明大页 | fork 性能下降 | 关闭 THP（transparent huge pages） |
| 单核绑定 | 子进程与主进程抢 CPU | 不绑定单核 |
| `appendfsync always` | 性能大幅下降 | 非强一致用 everysec |

## 3. 集群陷阱

| 陷阱 | 问题 | 正确做法 |
| :-- | :-- | :-- |
| 跨槽多 key 命令 | MGET/事务/Lua 报错 | 用哈希标签 `{}` 强制同槽 |
| 集群倾斜 | 热 key 集中某一分片 | 本地缓存、key 复制分散 |
| 大 Key 迁移 | 扩容迁移慢 | 拆分大 Key |
| 带宽消耗 | Gossip 通信占用带宽 | 合理规划节点规模 |
| 读写分离滥用 | 读到旧数据 | 强一致需求别用从节点读 |

## 4. 上线检查清单

上线前逐项确认：

| 类别 | 检查项 |
| :-- | :-- |
| 内存 | `maxmemory` 已设且留有余量 |
| 淘汰 | `maxmemory-policy` 符合业务（非 noeviction） |
| 持久化 | 主节点开启持久化，fsync 策略合理 |
| 过期 | 缓存 key 都设置了 TTL |
| 命令 | 无 KEYS、大 DEL 等危险命令 |
| 连接 | 客户端使用连接池，连接数可控 |
| 监控 | 内存、延迟、命中率已接入监控告警 |
| 高可用 | 哨兵/集群已配置，故障转移可验证 |

> 上线前的检查清单不是形式，而是把「踩过的坑」固化下来，避免重复犯错。
