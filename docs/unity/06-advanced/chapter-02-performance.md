# 性能优化概览

游戏跑起来掉帧、卡顿，你想优化但不知道从哪下手。读完这一篇，你能识别游戏性能的三大瓶颈来源，理解 Draw Call 和 GC 这两个核心概念，并按清单系统排查。

## 1. 性能问题从哪里来

游戏的每一帧都要在约 16.7 毫秒内完成（60 FPS）。性能问题的本质是**某件事占用了太多时间**，导致一帧做不完。占用时间的主要有三处：

| 来源 | 表现 | 典型原因 |
| --- | --- | --- |
| CPU（脚本） | 帧率低，Profiler 里脚本耗时高 | 每帧做昂贵操作、频繁查找、大量 GC |
| GPU（渲染） | 帧率低，Rendering 耗时高 | Draw Call 过多、模型面数高、纹理过大 |
| 内存 | 卡顿、闪退 | 只生成不销毁、资源泄漏、纹理未压缩 |

优化的第一步永远是**用 Profiler 定位**（见[调试与 Profiler](../05-engineering/chapter-04-debugging-profiler.md)），而不是凭感觉改。先知道瓶颈在哪，再针对优化。

## 2. Draw Call：渲染的计数单位

**Draw Call** 是 CPU 告诉 GPU"画一次"的指令。每帧的 Draw Call 数量是渲染性能的关键指标。

- 场景里每个使用不同材质的物体，通常会产生一个或多个 Draw Call。
- 1000 个各自独立的小物体，可能就有 1000 次 Draw Call，CPU 光是发指令就忙不过来。
- Draw Call 过多是移动端和低端机掉帧的头号原因。

优化的核心是**减少 Draw Call**，主要手段：

- **批处理（Batching）**：把多个用相同材质的物体合并成一次绘制。静态物体勾选 **Static Batching**，动态物体靠 **GPU Instancing** 或共享材质。
- **合并网格**：把多个小模型合并成一个大模型，减少物体数量。
- **共享材质**：尽量让多个物体用同一个材质，而不是每个物体一个材质。

在 Profiler 的 Rendering 区域能看到 Draw Call 数量，优化前先记一个基线，优化后对比。

## 3. GC：垃圾回收的代价

C# 有垃圾回收（GC），但 GC 不是免费的——它会扫描内存、回收不再使用的对象，这个过程可能暂停游戏。如果脚本每帧都创建大量临时对象，GC 频繁触发，就会造成周期性卡顿。

Unity 里最大的性能杀手之一就是**每帧分配（per-frame allocation）**：

```csharp
// 反例：每帧都创建新字符串和数组，产生 GC 压力
void Update()
{
    string s = "HP: " + health;                 // 字符串拼接产生垃圾
    var results = GetComponentsInChildren<Enemy>();  // 每帧分配数组
}
```

优化手段：

- **避免每帧创建对象**：把 `new`、字符串拼接、`GetComponent` 这类操作移出 `Update`，放到 `Start` 缓存。
- **用对象池（Object Pool）**：频繁生成销毁的物体（子弹、敌人），预先创建一批、循环复用，而不是反复 `Instantiate`/`Destroy`。
- **缓存组件引用**：`GetComponent` 的结果缓存到字段，不要每帧调用。

判断是否有 GC 问题：Profiler 里看 **GC Alloc**（每帧分配量），或看帧率是否周期性波动（GC 触发时的特征）。

## 4. 一个优化清单

按优先级排列的排查清单：

1. **Profiler 定位**：先确认瓶颈在 CPU、GPU 还是内存，别瞎猜。
2. **减少 Draw Call**：合并网格、共享材质、开批处理。
3. **消除每帧分配**：缓存引用、移出 `new`、用对象池。
4. **检查物体数量**：确认 `Instantiate` 都有对应的 `Destroy`，避免无限堆积。
5. **压缩资源**：纹理用合适的分辨率和压缩格式，音频用合适格式。
6. **降低物理开销**：减少不必要的 Rigidbody，合理设置 Fixed Timestep。

## 5. 优化与可读性的权衡

性能优化要避免"过度优化"。原则是：

- **先让游戏能跑、能玩，再优化**。过早优化会牺牲代码可读性，得不偿失。
- **优化要有数据支撑**。改之前 Profiler 记基线，改之后对比，确认真的变快了，而不是"感觉快了"。
- **优先优化热点**。Profiler 显示的最耗时的一两个点，往往贡献了大部分开销，集中改它们收益最大。

性能优化是持续的过程，不是一次性的。游戏开发中，先完成功能，再在关键时刻（明显卡顿、上线前）集中优化。
