# 游戏开发与 Unity 的定位

你会任意一门编程语言，但还没做过游戏。读完这一篇，你能说清游戏开发和普通应用开发的本质区别，理解 Unity 用「场景 + 组件 + 脚本」这套模型解决了什么问题，并知道它和 Godot、Unreal 的取舍。

## 1. 游戏开发与普通应用的区别

普通应用（网页、后台服务、命令行工具）大多是**事件驱动**的：程序启动后等待输入，收到请求就处理、返回结果，然后继续等待。两个请求之间程序可以完全空闲。

游戏是**帧驱动**的：无论玩家是否操作，画面都要以固定频率持续刷新。游戏世界里的物体每帧都在移动、碰撞、播放动画、响应物理，即使玩家什么都不做，这些状态也在持续演进。

```txt
普通应用：启动 → 等待事件 → 处理 → 返回 → 继续等待
游戏：     启动 → 每帧循环（读取输入 → 更新状态 → 渲染画面）→ 直到退出
```

这个区别带来三个直接后果：

- **实时性**：玩家按下跳跃键，角色必须在几十毫秒内做出反应，否则会感到"卡"。延迟的要求比大多数后台服务严格得多。
- **每帧都要算**：渲染、物理、动画、寻路都需要在每帧（约 16.7ms，对应 60 帧/秒）内完成。任何一帧超时都会表现为掉帧。
- **状态高度耦合**：一个角色的位置同时被输入、物理、动画、镜头等多个系统读写，比单次请求处理的状态管理复杂得多。

## 2. Unity 是什么

Unity 是 Unity Technologies 开发的游戏引擎，由三部分组成：

- **引擎运行时**：负责渲染、物理、动画、音频、输入、资源加载等底层能力。
- **编辑器**：一个可视化工具，用来搭建场景、摆放物体、调参数、看运行结果。
- **脚本层**：用 C# 写游戏逻辑，通过 Unity 提供的 API 驱动引擎。

三者的关系可以这样理解：引擎运行时提供能力，编辑器让你可视化地组装场景，脚本把"玩家按了跳跃键"这样的输入翻译成对引擎能力的调用。

## 3. Unity 用「场景 + 组件 + 脚本」解决什么问题

Unity 的核心模型只有三个概念，但贯穿所有工作：

### 3.1 场景（Scene）

场景是游戏世界的容器，可以理解成一个"关卡"或"一个界面"。一个 3D 场景里放着灯光、地形、角色、摄像机等物体。游戏运行时会加载某个场景，玩家看到和操作的就是这个场景里的内容。

### 3.2 游戏对象与组件（GameObject 与 Component）

Unity 里几乎一切可见、可交互的东西都是 **GameObject**（游戏对象）。但 GameObject 本身只是一个空容器，它没有任何行为。

行为由挂在它身上的**组件（Component）** 赋予。例如：

- 一个 GameObject 加上 `Transform` 组件，就有了位置、旋转和缩放；
- 加上 `Mesh Renderer` 组件，才能被渲染出来；
- 加上 `Rigidbody` 组件，才参与物理模拟；
- 加上你自己写的脚本组件，才有自定义逻辑。

这就是 Unity 的**组件化**思想：不通过继承一个庞大的"游戏物体"基类来获得能力，而是把能力拆成一个个小组件，按需组合。这比深继承层次更灵活，也更容易复用。

### 3.3 脚本（Script）

脚本是用 C# 写的组件。它继承 `MonoBehaviour`，Unity 在特定时机自动调用脚本里定义好的方法（如每帧调用 `Update`）。你写脚本就是在告诉 Unity："每帧把这个物体向前移动一段距离"或"玩家碰到这个物体时扣血"。

C# 语言本身不在这里展开，需要时看 [C# 专题](../../csharp/index.md)。

## 4. 为什么选 Unity：三选一

新手常问 Unity、Godot、Unreal 怎么选。它们不是"好坏"之分，而是取舍不同：

| 引擎 | 语言 | 强项 | 弱项 |
| --- | --- | --- | --- |
| Unity | C# | 生态最大、教程最多、跨平台最广（主机/PC/移动/Web）、2D 和 3D 都成熟 | 源码闭源、部分高级功能需付费订阅 |
| Unreal | C++ / 蓝图 | 画面天花板高、大厂 3A 常用 | 上手门槛高、2D 和移动端偏弱 |
| Godot | GDScript / C# | 完全开源免费、轻量 | 生态和教程相对少、主机支持弱 |

对"会编程但没做过游戏"的读者，Unity 的优势在于：C# 是工程友好的静态类型语言，官方和社区教程数量最多，遇到问题最容易找到答案。Unreal 适合追求极致画面的团队，Godot 适合偏好开源和轻量的个人开发者。

## 5. 一个最小工作流

把前三节串起来，Unity 里做一个小功能通常是这几步：

1. 在场景里放一个 GameObject（比如一个立方体）。
2. 给它挂组件：默认有 `Transform`，再加 `Mesh Renderer` 和 `Box Collider`。
3. 写一个 C# 脚本组件，在 `Update` 里让物体每帧旋转。
4. 把脚本挂到这个 GameObject 上，点播放，看到它转起来。

后面四篇会一步步带你完成这个过程：先装好环境（[安装 Unity Hub 与选择 LTS 版本](./chapter-02-installation.md)），再认识编辑器（[编辑器界面与工作区](./chapter-03-editor-workspace.md)），最后做出第一个会动的项目（[第一个项目：场景、GameObject 与组件](./chapter-04-first-project.md)）。
