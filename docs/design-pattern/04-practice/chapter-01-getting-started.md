# 设计模式入门

> 不是为了背 23 个模式的名字，而是为了在遇到设计问题时有现成的解决方案可以参考。

## 为什么要学设计模式

- **沟通**：说"用策略模式"比描述一段代码结构高效得多
- **经验复用**：前人踩过的坑和总结的方案，直接拿来用
- **代码质量**：模式是经过验证的、可维护的代码结构

## 从问题出发

```txt
代码难以扩展 → 开闭原则 → 策略模式 / 装饰器
创建逻辑复杂 → 工厂模式 / 建造者
对象间通信混乱 → 观察者 / 中介者
需要全局唯一 → 单例
接口不兼容 → 适配器
需要增强功能 → 装饰器 / 代理
```

## 学习顺序建议

1. 先理解 SOLID 原则（设计的底层逻辑）
2. 学习最常用的 5 个：策略、工厂、单例、观察者、代理
3. 按需学习其他模式（遇到问题再查）
4. 在实际项目中识别模式的应用

## 反模式提醒

- 不要为了用模式而用模式
- 简单代码不需要模式
- 过度设计比没有设计更糟糕
