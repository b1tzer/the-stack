# 为什么需要设计模式？

## 1. 从"烂代码"说起

```java
// 烂代码：大量 if-else
public void pay(String type, BigDecimal amount) {
    if ("alipay".equals(type)) {
        // 支付宝逻辑 50 行
    } else if ("wechat".equals(type)) {
        // 微信逻辑 50 行
    } else if ("bank".equals(type)) {
        // 银行卡逻辑 50 行
    }
    // 每次新增支付方式都要改这个方法...
}
```

问题：违反开闭原则，扩展困难，维护噩梦。

## 2. 设计模式是什么

前人总结的**解决特定问题的最佳实践**。

不是发明，是发现——从无数项目中提炼出的通用解法。

## 3. 学设计模式的好处

| 好处 | 说明 |
| :-- | :-- |
| 代码更优雅 | 减少重复，提高可读性 |
| 扩展更容易 | 新增功能不改旧代码 |
| 沟通更高效 | "用策略模式"比解释半天强 |
| 面试加分项 | 架构师必考 |

## 4. 怎么学不枯燥

每个模式我会用这个结构讲：

1. 🏠 **生活类比** — 30 秒讲明白
2. 💩 **烂代码** — 问题在哪
3. ✨ **模式方案** — 怎么改
4. 💻 **代码实现** — 可运行
5. 🔧 **框架应用** — Spring/JDK 中的真实例子
6. ⚠️ **适用场景** — 什么时候用、什么时候不用
