# 场景实战（Scenarios）

> 本专项按**业务场景**而非技术栈组织，回答「我要做一个具体功能，该怎么组合这些技术」的问题。每个场景聚焦一个技术挑战，遵循「需求 → 架构决策 → 关键实现 → 常见坑」的展开顺序。

## 定位与分工

The Stack 其余专项按技术栈组织，本专项按业务需求组织，两者互补：

| 专项 | 回答的问题 |
| :-- | :-- |
| `spring/` | 在 Spring 里如何使用某个组件（框架落地） |
| `engineering/` | 框架无关的软件工程方法论（怎么想） |
| 组件专项（Redis / Kafka / MySQL 等） | 组件本身的机制与命令（组件是什么） |
| **`scenarios/`（本专项）** | 一个业务场景该怎么组合这些技术（怎么做） |

本专项只引用、不复制：涉及具体技术实现时，用相对链接指向对应专项的权威章节。

## 场景全景

| 分区 | 主题 | 典型场景 |
| :-- | :-- | :-- |

| [数据访问](./04-data-access/) | 读写分离、多租户、分库分表 | 高并发读写、SaaS 隔离 |
| [综合案例](./05-cases/) | 多技术栈协同的完整业务系统 | 电商订单、排行榜、搜索引擎 |
