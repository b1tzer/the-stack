# 设计原则速查

## SOLID 原则

| 原则 | 缩写 | 一句话 | 违反症状 |
| :-- | :-- | :-- | :-- |
| 单一职责 | SRP | 一个类只做一件事 | 修改一个功能要改多个类 |
| 开闭原则 | OCP | 对扩展开放，对修改关闭 | 新增功能要修改已有代码 |
| 里氏替换 | LSP | 子类能替换父类 | 子类重写后行为不一致 |
| 接口隔离 | ISP | 接口要小而专 | 实现类被迫实现不需要的方法 |
| 依赖倒置 | DIP | 依赖抽象而非具体 | 高层模块直接依赖低层实现 |

## 其他原则

| 原则 | 说明 |
| :-- | :-- |
| DRY | Don't Repeat Yourself，消除重复 |
| KISS | Keep It Simple, Stupid，保持简单 |
| YAGNI | You Aren't Gonna Need It，不过度设计 |
| 组合优于继承 | 用组合代替继承，更灵活 |
| 最少知识原则 | 对象只与直接朋友交互 |
| 好莱坞原则 | 别调用我们，我们会调用你（IoC） |

## 代码坏味道

| 坏味道 | 症状 | 解药 |
| :-- | :-- | :-- |
| 重复代码 | 多处相同逻辑 | 提取方法/类 |
| 过长方法 | 一个方法几百行 | 拆分为小方法 |
| 过大类 | 一个类上千行 | 职责拆分 |
| 过长参数列表 | 方法参数超过 4 个 | 引入参数对象 |
| 发散式变化 | 一个类因多种原因修改 | SRP 拆分 |
| 霰弹式修改 | 一个修改涉及多个类 | 合并相关逻辑 |
| 依恋情结 | 方法大量使用其他类的数据 | 方法搬移到数据所在的类 |
| 数据泥团 | 多个数据总是一起出现 | 提取为对象 |
| 过度耦合 | 类之间依赖过深 | 引入接口/中介者 |
| 冗余类 | 类没有存在的意义 | 删除 |

## 重构手法

| 手法 | 说明 |
| :-- | :-- |
| 提取方法 | 将代码块提取为独立方法 |
| 提取类 | 将相关字段和方法提取为新类 |
| 内联方法 | 方法太简单时合并回调用方 |
| 以对象取代基本值 | 用对象包装原始类型（如 Money） |
| 以策略取代条件 | 用策略模式替换 if-else |
| 以多态取代条件 | 用多态替换 type 判断 |
| 引入参数对象 | 将多个参数封装为对象 |
| 搬移方法 | 将方法移到更合适的类 |
