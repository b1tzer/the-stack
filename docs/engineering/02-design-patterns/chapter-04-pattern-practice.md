# 模式实践

> 本章为概览。深入讲解见 [设计模式专题 · 实战](/design-pattern/04-practice/chapter-01-spring-patterns)。

## 何时用模式

- **识别问题**比套用模式更重要——先看清问题，再选模式
- 模式是**解决方案的命名**，不是设计的起点
- 过度设计比没有设计更危险

## 常见误区

| 误区 | 正确做法 |
|------|----------|
| 为了用模式而用模式 | 有明确痛点时才引入 |
| 一次用多个模式 | 逐步重构，一次解决一个问题 |
| 模式代码=固定模板 | 模式是思想，实现要适配上下文 |
| 所有地方都要模式 | 简单代码不需要模式 |

## 反模式速查

| 反模式 | 症状 | 解药 |
|--------|------|------|
| God Class | 一个类干所有事 | 职责拆分 |
| Golden Hammer | 什么问题都用同一个方案 | 多方案对比 |
| Copy-Paste | 复制代码代替抽象 | 提取公共逻辑 |
| Premature Optimization | 过早优化 | 先让它工作，再让它快 |
