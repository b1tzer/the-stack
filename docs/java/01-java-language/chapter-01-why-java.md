# Java 的设计目标与运行链路

Java 把源码编译为字节码，再由 JVM 在不同平台上执行。理解 Java 要解决的问题和这条运行链路，是继续学习类型系统、对象语义和 JVM 运行时的共同起点。

## 1. Java 要解决什么问题

Java 诞生时，开发者面对两个难题：手动内存管理带来的正确性风险，以及同一份程序难以跨平台运行。下面分别说明。

### 1.1 手动内存管理与复杂性控制

20 世纪 90 年代，C 和 C++ 广泛用于系统编程和应用开发。它们提供了接近硬件的控制能力，也把更多正确性责任交给开发者：

**C 的问题：** 开发者需要手动调用 `malloc()` 和 `free()`。遗漏释放会造成资源占用，重复释放会破坏内存状态，越界写入还可能覆盖其他程序数据。这些问题可能在程序运行很久之后才暴露，排查成本很高。

**C++ 的问题：** 面向对象机制帮助组织复杂系统，但多重继承、模板错误信息和手动内存管理也增加了认知负担。开发者需要在表达能力、抽象层次和错误风险之间持续权衡。

Java 的设计方向是降低这些风险：由运行时承担内存回收，由编译器和类型系统提前发现更多错误，同时保留面向对象的表达能力。

### 1.2 跨平台执行

C/C++ 程序通常需要针对目标平台编译。同一份源码可能要在 Windows、Linux 和 macOS 上分别构建，还要处理不同的系统调用、库和二进制格式。对于需要覆盖多种设备的软件，这会显著增加构建和维护成本。

Java 在源码和机器码之间加入字节码和 JVM，目标是让同一份程序无需针对每个平台重新编译源码。**一次编写，到处运行**描述的正是这一设计方向。

## 2. Java 的核心设计目标

Java 最初由 James Gosling 及其团队设计，当时名为 Oak。语言设计围绕以下目标展开。

### 2.1 一次编写，到处运行

Java 源码先由编译器转换为字节码，再由目标平台上的 JVM 执行。JVM 屏蔽操作系统和 CPU 指令集的差异，让应用依赖统一的字节码契约。

```txt
C/C++：Source → Machine Code → 针对目标平台运行
Java：  Source → Bytecode → JVM → 在安装对应 JVM 的平台上运行
```

### 2.2 自动内存管理

Java 不要求开发者手动释放普通对象内存。垃圾回收器（Garbage Collector，GC）识别不再可达的对象并回收其占用的堆空间。

这减少了悬空指针、Use-After-Free 和 Double Free 等错误，但不会消除所有内存问题。可达性判断不等于业务使用判断，一个已经不再被业务访问的对象，只要仍被静态集合或缓存引用，GC 仍会视其为存活。堆外内存未释放同样可能造成内存耗尽。

GC 也有成本：它会消耗 CPU，并在某些阶段暂停应用线程。是否可接受取决于堆大小、分配速率、延迟目标和收集器配置。

### 2.3 静态类型检查

Java 是静态类型语言。变量类型在编译期确定，编译器会在运行前检查明显的类型错误。例如，`String s = 123;` 无法通过编译。

类型检查不能发现所有运行时错误，例如空指针、数组越界和逻辑条件错误，但它把大量错误从生产环境提前到开发阶段。

### 2.4 字节码验证

JVM 在执行字节码前会进行验证，检查指令、类型和访问权限是否合法。这套机制用于降低非法字节码直接破坏运行时的风险。

字节码验证不是完整的安全沙箱。类加载机制、模块访问控制和操作系统权限分别约束不同层面的行为，不能互相替代。Java 17 起 Security Manager 已弃用（JEP 411），不应再作为新应用的安全隔离方案。

### 2.5 面向对象的组织方式

Java 代码通常以类、接口、枚举和记录作为组织单位，通过封装、继承和多态表达对象之间的关系。

面向对象不是唯一可用的编程方式。Java 也支持静态方法、函数式接口和不可变数据；关键在于根据状态所有权和变化方向选择合适的抽象，而不是机械套用继承。

### 2.6 向后兼容

Java 重视语言和字节码层面的兼容性。旧版本编译生成的字节码通常能在较新 JVM 上运行，但源码能否重新编译、程序行为是否一致，还取决于使用的 API、第三方依赖和运行环境。因此 JDK 升级不能只看编译是否通过。

## 3. Java 的性能取舍

Java 的设计目标不是在所有场景中追求极致性能，而是在性能、安全、可维护性和开发效率之间取得平衡。

C/C++ 可以直接控制内存布局，并允许更接近硬件的优化，因此在部分系统编程场景中仍有优势。Java 则通过垃圾回收、边界检查和运行时抽象承担更多自动化，也付出了相应开销。

JIT 编译可以根据运行时 profile 优化长期运行的服务端程序。在充分预热、分配模式稳定的部分工作负载中，Java 的吞吐量可以接近原生代码，但这不是保证；启动时间、短生命周期任务、尾延迟和特定数值计算仍可能更适合其他方案。

## 4. Java 代码如何运行

先用一个最小程序建立全局视角：

```java
public class Hello {
    public static void main(String[] args) {
        System.out.println("Hello, World!");
    }
}
```

假设这段代码保存在 `Hello.java`，用 JDK 17 或 21 编译并运行：

```txt
javac Hello.java
java Hello
```

`javac` 生成 `Hello.class`，内容是 JVM 字节码；`java Hello` 启动 JVM 加载并执行 `Hello` 类。这段代码从源码到 CPU 执行，主要经历以下步骤：
